# 進入層 DSL（住客掃碼頁）

這個模組的專屬句型。跨模組共用句型見 [`../dsl.md`](../dsl.md)。

掃碼進入、無法使用頁、重試狀態、憑證失效時的靜靜重換，以及與櫃檯 Web 的隔離。打開 `/g/{代碼}` 時畫面用代碼呼叫換 session（`POST /guest/scan`）：成功就進首頁；後端回 `409 room_vacant`（空房、代碼已作廢、代碼不存在、已退房都是這一個）顯示無法使用頁；回 `429`、連不上、`5xx` 顯示重試狀態。進首頁之後任何一次呼叫被回 `401`，畫面丟掉手上的憑證、用網址裡的代碼重換一次，換到就重發剛才那一次、畫面不變，換不到就依上面兩種結果顯示；一輪最多重換一次。憑證放這個分頁的儲存空間、鍵帶代碼；櫃檯 Web 的登入狀態用不同的鍵、不同的標頭，兩邊互相讀不到。

## Given 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 住客掃碼頁實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `主管在後台換掉了 "{房號}" 房的 QR Code` | `房號`：字串。 | 不支援 | 無 | `使用 fixture`：`BackendChannel`。`Arrange 來源`：以主管身分呼叫換 QR；舊代碼作廢、這間房既有的住客 session 全部撤銷。`回寫資料`：舊代碼與新代碼；之後「舊代碼的網址」用舊代碼，「QR Code 的網址」用新代碼。畫面已開啟時不通知它。 |
| `這支手機上的住客憑證已經不見` | 無 | 不支援 | 無 | `Arrange 來源`：清掉這個分頁儲存空間裡住客的憑證，網址不變，後端那邊的 session 仍有效。 |
| `這支手機上的住客憑證已經失效` | 無 | 不支援 | 無 | `使用 fixture`：`BackendChannel`。`Arrange 來源`：把這個分頁手上那枚 session 在後端撤銷（例如換 QR 再換回有效的代碼，或直接標記撤銷），分頁裡的憑證還在；下一次呼叫會被回 `401`，而網址裡的代碼仍換得到新 session。 |
| `"{房號}" 房這筆訂房已經過了退房時刻` | `房號`：字串。 | 不支援 | 無 | `使用 fixture`：後端 `Clock` 與瀏覽器時鐘。`Arrange 來源`：把兩邊的時間撥到這筆訂房的退房時刻之後；session 過期，再換也換不到（`room_vacant`）。 |
| `這支手機短時間內多次掃碼失敗，後端暫時不受理它的掃碼` | 無 | 不支援 | 無 | `使用 fixture`：`BackendChannel` 或網路攔截。`Arrange 來源`：從同一來源連續用不存在的代碼換 session 到超過後端的失敗次數門檻，讓接下來的換 session 都回 `429`；做不到時改以網路攔截讓換 session 回 `429`。 |
| `後端暫時出錯，任何掃碼都失敗` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：讓這個分頁的換 session 請求都回 `500`，其他請求不動，直到「後端已恢復」放行。 |
| `"{房號}" 房的住客的畫面停在重試狀態` | `房號`：字串。 | 不支援 | 停在重試狀態的原因是連不上後端。 | `Arrange 來源`：先讓這個分頁連不上後端，再開 `/g/{代碼}`。`等待條件`：重試狀態畫完。這時網路仍是斷的，由後面的句型放行。 |
| `這支手機已恢復連線` | 無 | 不支援 | 無 | `Arrange 來源`：放行網路攔截，接下來的請求正常到達後端。畫面不變。 |
| `後端已恢復` | 無 | 不支援 | 無 | `Arrange 來源`：放行「後端暫時出錯」的攔截。畫面不變。 |
| `"{房號}" 房的住客打開清單時因為後端出錯停在重試狀態` | `房號`：字串。 | 不支援 | 無 | `Arrange 來源`：先開首頁、讓憑證失效、讓後端出錯，再開我的需求清單的網址。`等待條件`：重試狀態畫完，網址仍是清單那一頁。 |
| `"{員工}" 已在這支手機上登入過櫃檯 Web，登入狀態還在` | `員工`：字串。 | 不支援 | 無 | `使用 fixture`：同一個瀏覽器環境的另一個分頁。`Arrange 來源`：在那個分頁以該員工登入櫃檯 Web 並停在總覽看板，登入憑證留在那個分頁的儲存空間；住客用的是同一個瀏覽器環境的新分頁。 |
| `"{員工}" 已在這支手機上打開過 "{房號}" 房的住客頁` | `員工`：字串。<br>`房號`：字串。 | 不支援 | 無 | `Arrange 來源`：在住客的分頁用代碼開 `/g/{代碼}` 進首頁。 |

## When 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 住客掃碼頁實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `住客打開 "{房號}" 房舊代碼的網址` | `房號`：字串。 | 不支援 | 無 | `頁面操作`：用換 QR 之前的舊代碼開 `/g/{舊代碼}`。`等待條件`：無法使用頁或其他結果畫完。 |
| `住客打開一個不存在的代碼的網址` | 無 | 不支援 | 代碼是 22 個 base62 字元的隨機字串，後端查無。 | `頁面操作`：開 `/g/{不存在的代碼}`。`等待條件`：同上。 |
| `住客把網頁關掉，再從歷史記錄打開同一個網址` | 無 | 不支援 | 無 | `頁面操作`：記下目前網址，關掉這個分頁，在同一個瀏覽器環境開新分頁並開同一個網址（新分頁沒有住客憑證，網址帶代碼）。`等待條件`：畫面畫完。 |
| `住客在同一支手機上打開櫃檯 Web 的網址` | 無 | 不支援 | 無 | `頁面操作`：在同一個瀏覽器環境開預設飯店的櫃檯 Web 網址（`/{飯店代碼}/`）。`等待條件`：登入頁或總覽看板畫完。 |

## Then 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 住客掃碼頁實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `從打開網址到看到首頁，住客沒有輸入或按過任何東西` | 無 | 不支援 | 無 | `必查`：When 記下的輸入與點按次數是 0；過程中沒有出現過輸入框、登入頁或要按「同意」的東西。 |
| `過程中沒有要住客再掃一次 QR Code，也沒有出現錯誤訊息` | 無 | 不支援 | 無 | `必查`：從 When 開始到現在網址裡的代碼沒有變、沒有出現過重試狀態或任何錯誤文字（「連線失敗」「錯誤」「失敗」）、也沒有要住客輸入的東西；畫面上沒有提示浮層。 |
| `無法使用頁的文字與空房那一頁完全相同` | 無 | 不支援 | 無 | `必查`：畫面上的全部可見文字，與用 308 房（空房）的代碼開出來的無法使用頁的全部可見文字逐字相同（標題、內文、「櫃檯（24 小時）」「房內電話撥 9」）。 |
| `畫面上沒有任何可以點的東西` | 無 | 不支援 | 無 | `必查`：畫面上沒有按鈕、連結或可點的列；「櫃檯（24 小時）／房內電話撥 9」那張卡不是連結。 |
| `住客頁向後端的請求沒有帶員工的登入憑證` | 無 | 不支援 | 無 | `必查`：這個分頁從開網址到現在對後端的每一次請求都只帶住客的標頭（`X-Guest-Session`），沒有 `Authorization` 標頭；首頁讀到的是 311 房住客的資料。 |
| `櫃檯 Web 仍是 "{員工}" 的登入狀態，畫面是總覽看板` | `員工`：字串。 | 不支援 | 無 | `必查`：櫃檯 Web 那個分頁仍有該員工的登入憑證，畫面是總覽看板、帳號卡是他的姓名；沒有回到登入頁。 |
| `櫃檯 Web 顯示登入頁` | 無 | 不支援 | 無 | `必查`：櫃檯 Web 的分頁畫的是登入頁（有「登入」鈕），沒有總覽看板；它的儲存空間裡沒有員工的登入憑證。 |
