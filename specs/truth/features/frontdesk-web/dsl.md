# 櫃檯 Web 共用 DSL

這裡只放跨模組共用的句型。模組專屬句型寫在 `{模組}/dsl.md`。

**BDD techstack**：`Cucumber-JVM` ＋ `Playwright for Java`，獨立 Maven 模組 `app/web-bdd/`，自己的 glue 套件；後端資料準備用 `app/bdd-support/` 的 `BackendChannel`，與員工 App 的測試線共用（見 `specs/truth/techstack.md`）。櫃檯 Web 的程式在 `app/web/`，直接呼叫 `tms` 後端。

**共通實作約定**（每個 row 都適用，不再逐列重複）：

- **飯店與帳號**：預設飯店是「雅典娜酒店」，識別代碼 `athena`，客房在 2 至 5 樓，房號第一碼就是樓層。預設帳號如下，密碼都是 `Tms12345`，都不是臨時密碼、沒有被鎖定或停用；句型裡寫姓名就代表這個帳號。

  | 姓名 | 員工編號 | 角色 |
  | --- | --- | --- |
  | 林佩君、何志偉、阮氏香、許雅婷 | F0101、F0102、F0103、F0199 | 櫃檯（`frontdesk`） |
  | 張主管 | M0001 | 主管（`manager`） |
  | 吳家豪 | D0001 | 值班主管（`duty_manager`） |
  | 小美、小林、小陳、阿美 | H0201、H0202、H0203、H0204 | 房務（`housekeeping`） |
  | 阿強 | E0301 | 工務（`engineering`） |
  | 陳老闆 | O0001 | 老闆（`owner`） |

- **時間**：後端的可調 `Clock` 與瀏覽器的時鐘（Playwright 的時鐘控制）一起設定。沒有宣告時今天是 2026 年 10/26 週一、現在時間 14:10。
- **常用回覆**：預設飯店的住客資訊頁有五頁，依序是「早餐時間」（全文「早餐 07:00–10:00，在 2 樓自助餐廳，憑房卡入場。」）、「Wi-Fi」、「退房時間」、「健身房」、「叫車」。
- **瀏覽器設定**：沒有宣告時用「電腦 1280 × 720 滑鼠」。整套 feature 另以「iPad 橫向 1180 × 820 觸控」（WebKit、觸控輸入）再跑一次；兩組設定的結果都要成立，這就是「滑鼠與觸控都能完成所有操作」的驗收方式。句型明寫 `用的是` 時只跑指定的那一組。
- **找畫面元素**：一律以使用者看得到的角色與文字找（按鈕的名稱、欄名、標題），不用版面座標；元素的定位方式留在 page object 內。
- **登入狀態**：Given 的「已登入」可以直接把登入回應寫進這個分頁的儲存空間來略過登入頁；只有驗登入頁本身的句型才真的走一次畫面。
- **畫面斷言**：Then 取畫面上看得到的文字；凡是寫「後端」的 Then 另以 `BackendChannel` 讀後端的權威狀態，畫面與後端都要成立。等待畫面更新時用輪詢，上限 5 秒，句型另有寫秒數的照句型。
- **單的識別**：句中的房號代表本案例 Given 裡那間房唯一的一張單；同一間房有兩張單時，用標題分辨。
- **文字比對**：畫面文字預設比對繁體中文介面。「」內的字是畫面文字的一部分，照字面比對。

## 單的狀況對照

`全館有以下的單：` 的 `狀況` 欄用下面的說法，每一種都對到後端既有的狀態值，不是新的狀態。

看板分欄的規則：「已完成」欄只放完成了、還在等查房或等驗收的單；後端已經結束的單（`ended_at` 有值）一律在「已結案」欄，包括查房通過、免查房、工務單結案、當場回答、取消，以及完成的備品與其他類的單。

| 狀況 | 後端的樣子 | 看板的欄 |
| --- | --- | --- |
| 待派單 | `triage`，`dept` 是 `frontdesk` | 待派單 |
| 待認領 | `pool`，沒有負責人 | 待認領 |
| 已接（班前排房）、已接（自己認領）、已接（主管指派）、已接（被轉派） | `accepted`；最近一筆到手的事件分別是系統的 `assigned`、本人的 `claimed`、主管的 `assigned`、主管的 `reassigned` | 已接 |
| 進行中 | `doing` | 進行中 |
| 待查房 | 打掃單的 `done`，還沒查房 | 已完成 |
| 已完修 | 修繕單的 `done`，等主管驗收 | 已完成 |
| 已完成 | 備品或其他類的 `done`，完成當下就結束（`ended_at` 有值） | 已結案 |
| 中斷（請假）、中斷（本人暫停） | `interrupted`；後者的中斷是負責人自己做的 | 中斷 |
| 延後中（主管延後）、延後中（本人延後） | `deferred`；後者 `deferred_by_self` 為 true | 延後中 |
| 查房通過、免查房 | `inspected`，`inspection` 分別是 `passed`、`waived` | 已結案 |
| 已結案（驗收通過）、已結案（不需處理） | 修繕單的 `closed`；後者完修結果是 `no_action_needed` | 已結案 |
| 已取消（住客收回）、已取消（主管取消）、已取消（排房被取代）、已取消（同仁撤回） | `cancelled`，`cancel_reason` 分別是 `guest_withdrew`、`manager_void`、`plan_superseded`、`staff_withdrew` | 已結案 |
| 已回答 | `done` 且 `tasks.answer` 有值，`dept` 是 `frontdesk` | 已結案 |

## Given 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `今天是 "{日期}"` | `日期`：字串 `M/D`；年份固定 2026。 | 不支援 | 無 | `使用 fixture`：後端 `Clock` 與瀏覽器時鐘。`Arrange 來源`：把兩邊的日期設成該日，時刻維持 14:10。 |
| `現在時間是 "{時刻}"` | `時刻`：字串 `HH:mm`。 | 不支援 | 無 | `使用 fixture`：同上。`Arrange 來源`：把兩邊的時刻設成今日該時刻；畫面已開啟時，同步推進瀏覽器時鐘並等畫面重算分鐘數。 |
| `全館有以下的單：` | 無 | 支援：`房號`（必填，字串）、`狀況`（必填，字串；見「單的狀況對照」）、`標題`（選填，字串）、`類型`（選填，字串；打掃、備品、修繕、其他）、`部門`（選填，字串；房務、工務、未分部門）、`負責人`（選填，字串）、`住客`（選填，字串；姓名或「空房」）、`VIP`（選填，是或否）、`入住日`、`退房日`（選填，字串 `M/D`）、`來源`（選填，字串；住客掃碼、櫃檯開單、系統排房、同仁報修）、`住客原話`（選填，字串；有填就是住客打字的需求）、`原文語言`（選填，字串；日文、英文）、`翻譯`（選填，字串；單上既有的翻譯內容）、`時間`（選填，字串；`HH:mm`、`昨天 HH:mm`、`前天 HH:mm`、`N 天前 HH:mm` 或 `N 分鐘前`。它是這個狀況的計時起點：待派單是住客送出、待認領是開始等待、已接是到手、進行中是第一次開始（中途中斷、停下的時間也算在內，不是累計工時，和員工 App 的計時不同）、中斷是中斷、延後中是延後，其餘是完成或結束的時刻）、`建立`（選填，字串 `HH:mm`；建立時間與 `時間` 不同時才填）、`派出時間`、`到手時間`（選填，字串 `HH:mm`；櫃檯派出與同仁到手的時刻）、`派單方式`（選填，字串；按鈕、拖曳）、`經手人`（選填，字串；依狀況是派單或回答的櫃檯、指派、轉派、延後、取消、查房或驗收的主管、開單或報修的人）、`原負責人`（選填，字串；被轉派時）、`說明`（選填，字串；依狀況是交代、本人填的原因或當場回答的回覆）、`SOP`（選填，字串 `已做/總數`）、`單號`（選填，字串）、`急件`（選填，是或否）、`對應品項`（選填，字串；這張單對應的品項鍵（中文品名），寫進 `tasks.note` 的 `menu_key`，看板卡片的 `menuKey` 就是它；住客勾選的單、櫃檯代開的品項單、住客打字但已對應到品項的單才有，留空代表沒有） | `類型`：部門是工務時是修繕（部門是工務的單一律是工務單）；其餘有 `住客原話` 時是其他，其餘是備品。<br>`部門`：打掃與備品是房務、修繕是工務；待派單與已回答是未分部門。<br>`住客`：有一位不是 VIP 的住客，姓名由測試自編。<br>`來源`：有 `住客原話` 或類型是備品時是住客掃碼，打掃是系統排房，修繕是同仁報修。<br>`時間`：0 分鐘前。<br>`派單方式`：按鈕。 | `使用 fixture`：`BackendChannel`。`Arrange 來源`：逐列在後端建立任務、訂房與能推導出該狀況的事件歷程（含 `task_no` 或工務單號、`ended_at`、`answer`）；有 `經手人` 與 `派出時間` 的待認領單代表它是櫃檯派出的，歷程有一筆 `triaged`；派給工務的這種單同時是一張工務單（類別其他、報修人是經手人、單號是 `單號` 欄或下一個 `W-` 號），對外顯示 `W-` 單號。部門是工務的單一律有工務單，不建出沒有工務單的工務部門單。表格以外全館沒有其他的單。`回寫資料`：房號（與標題）對應的 task id。可以寫在背景，同一案例再寫一次時是追加。 |
| `"{員工}" 已登入櫃檯畫面，停在 "{頁}"` | `員工`：字串。<br>`頁`：字串；總覽看板、待派單頁、設定頁。 | 不支援 | 無 | `使用 fixture`：登入狀態。`Arrange 來源`：以該員工取得登入回應並放進這個分頁，開啟該頁。`等待條件`：看板資料載入完成（設定頁另等設定讀完），側欄照該頁的預設（總覽看板與設定頁收起、待派單頁打開）。 |
| `"{員工}" 已登入櫃檯畫面，介面語言是 "{語言}"，停在 "{頁}"` | `員工`：字串。<br>`語言`：字串。<br>`頁`：字串。 | 不支援 | 無 | `Arrange 來源`：先把這台裝置上該員工的介面語言記成該語言，再以他登入並開啟該頁。 |
| `"{員工}" 已自己把側欄打開` | `員工`：字串。 | 不支援 | 無 | `頁面操作`：按工具列的「打開側欄」。`等待條件`：側欄展開。算是他自己選過側欄的樣子。 |
| `"{員工}" 已從側欄換到待派單頁` | `員工`：字串。 | 不支援 | 無 | `頁面操作`：側欄收起時先打開，再點「待派單」。`等待條件`：待派單頁載入完成。 |
| `"{員工}" 用的是 "{裝置}"` | `員工`：字串。<br>`裝置`：字串；`電腦 1280 × 720 滑鼠`、`iPad 橫向 1180 × 820 觸控`。 | 不支援 | 無 | `使用 fixture`：瀏覽器設定。`Arrange 來源`：以該組視窗尺寸與輸入方式開瀏覽器；寫在登入之後時，用同一份登入狀態在該設定下重開畫面。只跑這一組設定。 |
| `"{員工}" 開著 "{房號}" 的詳情面板` | `員工`：字串。<br>`房號`：字串。 | 不支援 | 無 | `Arrange 來源`：還沒登入時先以該員工登入並開啟總覽看板。`頁面操作`：點該房的卡片。`等待條件`：詳情面板的內容載入完成。 |
| `"{員工}" 的畫面還沒跟上，"{同事}" 已在另一台櫃檯把 "{房號}" 派給 "{部門}"` | `員工`、`同事`：字串。<br>`房號`：字串。<br>`部門`：字串；房務、工務。 | 不支援 | 無 | `使用 fixture`：`BackendChannel` 與網路攔截。`Arrange 來源`：先暫停這個分頁的即時訊號與定時重抓，再以同事的身分在後端派單（`deskAssignTask`）。畫面仍把這張單顯示成待派單。 |
| `"{員工}" 的畫面還沒跟上，"{同事}" 已在另一台櫃檯當場回答 "{房號}"` | `員工`、`同事`：字串。<br>`房號`：字串。 | 不支援 | 回覆內容由測試自編。 | 同上，同事在後端當場回答（`deskAnswerTask`）。 |
| `"{員工}" 的畫面還沒跟上，"{房號}" 的住客已自己收回需求` | `員工`：字串。<br>`房號`：字串。 | 不支援 | 無 | 同上，以住客身分在後端收回（`cancelGuestRequest`）。 |
| `接下來的送出會因為網路中斷而失敗` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：讓這個分頁接下來對派單、復原、當場回答、代開單、改設定的請求在送出時斷線，請求沒有到達後端；讀取不受影響。 |
| `看板資料的回應被延後` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：扣住 `getDeskBoard` 的回應不放，直到案例結束。 |
| `看板資料的讀取會失敗` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：讓 `getDeskBoard` 的每一次請求都斷線。 |

## When 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `"{員工}" 登入後打開 "{頁}"` | `員工`：字串。<br>`頁`：字串；總覽看板、待派單頁、詳情面板、當場回答面板、帳號面板。 | 不支援 | 寫面板時，是在總覽看板打開案例裡第一張待派單的詳情面板或當場回答面板，或打開帳號面板。 | `頁面操作`：以該員工登入（已登入時沿用），開啟該頁的網址；面板再多一步點開。`等待條件`：資料載入完成，沒有骨架。`回寫資料`：無。 |
| `"{員工}" 登入後打開 "{頁}"，資料還沒回來` | 同上；`頁` 只有總覽看板、待派單頁。 | 不支援 | 無 | `頁面操作`：同上，但不等資料。`等待條件`：外框已經畫出來、`getDeskBoard` 還沒有回應。 |
| `"{員工}" 按 "{按鈕}"` | `員工`：字串。<br>`按鈕`：字串；畫面上那顆可以按的東西的名稱。 | 不支援 | 無 | `頁面操作`：在最上面那一層（對話框、面板、頁面的順序）找名稱相符、看得到的按鈕或可點的列，按一下；觸控設定下用點觸。`等待條件`：這一下引發的請求與畫面變化都結束。點了沒有反應的入口不等待，直接往下驗。 |
| `"{員工}" 打開 "{房號}" 的詳情面板` | `員工`：字串。<br>`房號`：字串。 | 不支援 | 無 | `頁面操作`：在總覽看板點該房的卡片；在待派單頁點該房那一列右側動作以外的位置。`等待條件`：面板滑出並載入完成。 |
| `"{員工}" 從側欄換到 "{頁}"` | `員工`：字串。<br>`頁`：字串；總覽看板、待派單頁、設定頁。 | 不支援 | 無 | `頁面操作`：側欄收起時先打開，再點「總覽看板」「待派單」或「設定」。`等待條件`：該頁載入完成。 |
| `"{員工}" 在待派單頁按 "{房號}" 這一列的 "{動作}"` | `員工`：字串。<br>`房號`：字串。<br>`動作`：字串；派給房務、派給工務、當場回答…。 | 不支援 | 無 | `頁面操作`：在該房那一列按那顆動作。`等待條件`：派單時等請求結束與畫面變化；當場回答時等面板打開。`回寫資料`：這次請求的結果。 |
| `"{員工}" 在手機上{動作} "{房號}"` | `員工`：字串；房務、工務同仁或主管。<br>`動作`：認領、開始、完成、查房通過。<br>`房號`：字串。 | 不支援 | 無 | `使用 fixture`：`BackendChannel`。`頁面操作`：無；以該員工的身分在後端做這個動作（`tasksClaim`、`tasksStart`、`tasksComplete`、查房全部通過）。`等待條件`：後端回應成功。櫃檯的畫面靠即時訊號自己更新，測試不重新整理。 |

## Then 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `畫面上看得到以下文字：` | 無 | 支援：`文字`（必填，字串） | 無 | `必查`：每一列的文字都在畫面上看得到（不是藏起來的元素），照字面比對。 |
| `畫面上沒有以下文字：` | 無 | 支援：`文字`（必填，字串） | 無 | `必查`：每一列的文字在整個畫面上都找不到，包含捲出視窗外的部分。 |
| `畫面上看得到 "{文字}"` | `文字`：字串。 | 不支援 | 無 | 同 `畫面上看得到以下文字：`，只有一句。 |
| `畫面上沒有 "{文字}"` | `文字`：字串。 | 不支援 | 無 | 同 `畫面上沒有以下文字：`，只有一句。 |
