# 即時更新 DSL（櫃檯 Web）

這個模組的專屬句型。跨模組共用句型見 [`../dsl.md`](../dsl.md)。

即時更新與連線異常提醒列：畫面以 `fetch` 讀員工事件串流（`staffStream`）。訊號帶著那張單在看板上現在的樣子（整張卡片或「不在看板上」）與它是第幾步，畫面記著每張卡片是第幾步：比畫面上新的就直接換上或拿掉那一張，一樣或較舊的不理，平常不重讀 `getDeskBoard`；剛連上、恢復、發現中間漏了訊號、營業日換了、訊號看不懂時才重讀整份看板，重讀期間收到的較新卡片不會被讀回來的舊資料蓋掉。營業日到了換日時刻（`businessDate` 的隔天 00:00，時差照 `serverTime`，用後端時間校正後的現在去等），就算沒有任何訊號，畫面也自己重讀一次整份看板，昨天結束的卡片跟著拿掉；讀回來的 `businessDate` 還沒換，一分鐘後再讀一次。連線中斷後重連失敗、超過 35 秒沒有任何訊號、後端宣告降級、已有資料之後重讀失敗時顯示提醒列並改成定時重讀，恢復後提醒列自己消失。斷線後第一次重連就成功時，提醒列完全不出現。提醒列上寫「每 5 秒自動更新」，意思是資料最多落後 5 秒；定時重讀（連線異常時與讀取失敗後的自動再試）實際每 4 秒一次，讓重讀本身花的時間也算在 5 秒之內。測試以網路攔截控制這個分頁的串流連線，並可以代替後端送出指定的訊號；代替後端送出的卡片，以畫面上那張單目前的卡片為底，只改該狀況需要的欄位（`state`、負責人、時間）與步數。「幾秒內」用真實時間量。

**用語對照**：

| 用語 | 權威值 |
| --- | --- |
| 第 N 步 | `DeskTask.seq`；代替後端送出的訊號 `seq` 與 `card_seq` 都是 N |
| 卡片、不在看板上 | `task` 的 `board`：`upsert`（並帶 `card`）、`remove` |
| 沒有帶卡片的單變化訊號 | `task` 只有 `stream_pos`、`task_id`、`seq`、`type`，沒有 `board` |
| 營業日是隔天的單變化訊號 | `task` 的 `board`=`upsert`，`business_date` 是畫面上看板 `businessDate` 的隔天 |
| 看不懂的單變化訊號 | `task` 的 `board` 是 `upsert`、`remove` 以外的值，或 `data` 不是合法的 JSON |

## Given 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `即時連線已經中斷，提醒列出現了` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：切斷這個分頁的串流連線並擋住重連。`等待條件`：提醒列出現。 |
| `畫面上 "{房號}" 的卡片是第 {步數} 步` | `房號`：字串。<br>`步數`：整數。 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：把 `getDeskBoard` 回應裡這張卡片的 `seq` 改成該數字，觸發一次整份重讀。`等待條件`：重讀完成、卡片顯示。`回寫資料`：從這一刻開始記錄 `getDeskBoard` 的請求時間。 |
| `下一次讀取看板會被扣住，讀回來的 "{房號}" 仍是第 {步數} 步、狀況是 "{狀況}"` | `房號`：字串。<br>`步數`：整數。<br>`狀況`：字串；見介面根「單的狀況對照」。 | 不支援 | 無 | `使用 fixture`：網路攔截。`Arrange 來源`：下一次 `getDeskBoard` 的回應先扣住不放，內容裡這張卡片的 `seq` 是該步數、狀況是該狀況；由 `扣住的看板資料讀回來了` 放行。 |
| `即時連線中斷後已經恢復，提醒列消失了` | 無 | 不支援 | 無 | `Arrange 來源`：先切斷串流、等提醒列出現，再放行重連。`等待條件`：提醒列消失。`回寫資料`：從這一刻開始記錄 `getDeskBoard` 的請求時間。 |

## When 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `"{房號}" 的住客送出一張猜不準部門的打字需求 "{內容}"` | `房號`：字串。<br>`內容`：字串。 | 不支援 | 無 | `使用 fixture`：`BackendChannel`。`頁面操作`：無；以該房住客的身分在後端送出不命中任何分類規則的文字。`回寫資料`：送出的時刻。 |
| `"{同事}" 在另一台櫃檯把 "{房號}" 派給 "{部門}"` | `同事`：字串。<br>`房號`：字串。<br>`部門`：字串。 | 不支援 | 無 | `頁面操作`：無；以同事的身分在後端呼叫 `deskAssignTask`。`回寫資料`：送出的時刻。 |
| `"{房號}" 的住客自己收回需求` | `房號`：字串。 | 不支援 | 無 | `頁面操作`：無；以住客身分在後端收回。`回寫資料`：送出的時刻。 |
| `後端送來 "{房號}" 第 {步數} 步的卡片，狀況是 "{狀況}"` | `房號`：字串。<br>`步數`：整數。<br>`狀況`：字串；見介面根「單的狀況對照」。 | 不支援 | 無 | `頁面操作`：在這個分頁的串流裡送進一則 `task`：`task_id` 是這張單、`seq` 與 `card_seq` 都是該步數、`board`=`upsert`、`business_date` 等於畫面上看板的 `businessDate`，`card` 是改成該狀況與該步數的卡片。`回寫資料`：送出的時刻。 |
| `後端送來 "{房號}" 第 {步數} 步，說它已經不在看板上` | `房號`：字串。<br>`步數`：整數。 | 不支援 | 無 | `頁面操作`：在這個分頁的串流裡送進一則 `task`：`task_id` 是這張單、`seq` 與 `card_seq` 都是該步數、`board`=`remove`、`business_date` 等於畫面上看板的 `businessDate`，沒有 `card`。`回寫資料`：送出的時刻。 |
| `後端送來畫面上沒有的 "{房號}" 卡片，狀況是 "{狀況}"` | `房號`：字串。<br>`狀況`：字串；見介面根「單的狀況對照」。 | 不支援 | 無 | `頁面操作`：在這個分頁的串流裡送進一則 `task`：`task_id` 是新產生的 id、`seq` 與 `card_seq` 都是 1、`board`=`upsert`，`card` 是一張該房、該狀況的新卡片。`回寫資料`：送出的時刻。 |
| `後端送來一則 "{種類}"` | `種類`：字串；沒有帶卡片的單變化訊號、營業日是隔天的單變化訊號、看不懂的單變化訊號（見用語對照）。 | 不支援 | 無 | `頁面操作`：在這個分頁的串流裡送進一則該種類的 `task`，`task_id` 是畫面上第一張卡片的單、`seq` 比它的步數多 1。`回寫資料`：送出的時刻。 |
| `時間走到隔天 "{時刻}"，這段期間現場沒有任何變化` | `時刻`：字串 `HH:mm`；隔天的時刻。 | 不支援 | 無 | `使用 fixture`：後端 `Clock`、瀏覽器時鐘與網路攔截。`頁面操作`：不操作畫面。先把後端 `Clock` 設成隔天該時刻，再把瀏覽器時鐘往後推到同一刻；瀏覽器時鐘每次推 10 秒，每推一步就代替後端在串流裡送一則 `degraded` 為 false 的心跳，讓畫面不會因為太久沒有訊號而出現提醒列；期間不送任何 `task`，後端也沒有任何單的變化。`回寫資料`：推到該時刻的那一刻，當作「送出的時刻」。 |
| `扣住的看板資料讀回來了` | 無 | 不支援 | 無 | `頁面操作`：放行被扣住的 `getDeskBoard` 回應。`等待條件`：畫面處理完這份回應。 |
| `即時連線中斷` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`頁面操作`：切斷這個分頁的串流連線並擋住之後每一次重連，所以畫面的第一次重連一定失敗。 |
| `即時連線中斷，第一次重連就成功` | 無 | 不支援 | 無 | `使用 fixture`：網路攔截。`頁面操作`：在切斷之前就開始監看提醒列；切斷這個分頁的串流連線，放行畫面的第一次重連，重連後後端送來 `init`、`resync` 與 `degraded` 為 false 的心跳。`等待條件`：重連成功並收到 `init`。`回寫資料`：從切斷到現在，提醒列有沒有出現過（閃一下也算）。 |
| `後端宣告即時訊號可能延遲` | 無 | 不支援 | 無 | `頁面操作`：在這個分頁的串流裡送進一則 `degraded`。 |
| `超過 {秒數} 秒沒有收到後端的任何訊號` | `秒數`：整數。 | 不支援 | 無 | `頁面操作`：讓串流連線維持著但扣住所有訊號（含心跳），把瀏覽器時鐘往後推該秒數再多 1 秒。 |
| `即時連線恢復` | 無 | 不支援 | 無 | `頁面操作`：放行串流重連；重連後後端送來 `init`、`resync` 與 `degraded` 為 false 的心跳。 |
| `後端連不上，重新讀取看板失敗` | 無 | 不支援 | 無 | `頁面操作`：讓 `getDeskBoard` 與串流都斷線，並觸發一次重讀（送進一則即時訊號或推進時鐘）。 |

## Then 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 櫃檯 Web 實作語意（Playwright） |
| --- | --- | --- | --- | --- |
| `{秒數} 秒內 "{房號}" 的卡片出現在 "{欄}" 欄` | `秒數`：整數。<br>`房號`：字串。<br>`欄`：字串。 | 不支援 | 無 | `必查`：從 When 送出的時刻起算該秒數內，該房的卡片出現在那一欄（輪詢等待，超過就失敗）；期間測試沒有重新整理也沒有操作畫面。 |
| `{秒數} 秒內 "{房號}" 的卡片有負責人頭像 "{頭像}"，等待膠囊是 "{膠囊}"` | `秒數`：整數。<br>`房號`：字串。<br>`頭像`：字串。<br>`膠囊`：字串。 | 不支援 | 無 | `必查`：該秒數內那張卡片的頭像與膠囊文字相符。 |
| `{秒數} 秒內側欄 "{功能}" 的徽章與 "{數量卡}" 數量卡都變成 {數字}` | `秒數`：整數。<br>`功能`：字串。<br>`數量卡`：字串。<br>`數字`：整數。 | 不支援 | 無 | `必查`：該秒數內側欄徽章與那張數量卡的數字都等於該數字。 |
| `{秒數} 秒內待派單頁的清單沒有 "{房號}"，側欄 "{功能}" 的徽章是 {數字}` | `秒數`：整數。<br>`房號`：字串。<br>`功能`：字串。<br>`數字`：整數。 | 不支援 | 無 | `必查`：該秒數內清單沒有該房那一列，徽章等於該數字。 |
| `{秒數} 秒內待派單頁的清單第一筆是 "{房號}"` | `秒數`：整數。<br>`房號`：字串。 | 不支援 | 無 | `必查`：該秒數內清單最上面那一列是該房。 |
| `工具列下方出現提醒列 "{標題}"，說明是 "{說明}"` | `標題`：字串。<br>`說明`：字串。 | 不支援 | 無 | `必查`：工具列下方、內容區上緣有一條提醒列，兩段文字照字面相符；頁副標的字不變。 |
| `提醒列上沒有任何按鈕` | 無 | 不支援 | 無 | `必查`：提醒列裡沒有任何可以按的東西。 |
| `這段期間提醒列一次也沒有出現` | 無 | 不支援 | 無 | `必查`：When 記下的監看結果是提醒列從切斷到重連成功都沒有出現過；再等 2 秒，畫面上仍沒有提醒列。 |
| `這段期間 "{員工}" 沒有按任何東西` | `員工`：字串。 | 不支援 | 無 | `必查`：從 Given 結束到現在，測試沒有對畫面做任何點按或輸入，也沒有重新整理。 |
| `"{房號}" 的卡片仍在 "{欄}" 欄` | `房號`：字串。<br>`欄`：字串。 | 不支援 | 無 | `必查`：When 之後再等 2 秒，該房的卡片仍在那一欄，內容與 When 之前相同或是 When 之後才換上的較新那一份。 |
| `{秒數} 秒內看板上沒有 "{房號}" 的卡片` | `秒數`：整數。<br>`房號`：字串。 | 不支援 | 無 | `必查`：從 When 送出的時刻起算該秒數內，看板的每一欄都沒有該房的卡片，側欄徽章與數量卡跟著少算它。 |
| `這段期間畫面沒有重新讀取整份看板` | 無 | 不支援 | 無 | `必查`：從 Given 結束到現在再多等 2 秒，這個分頁沒有送出任何 `getDeskBoard` 請求。 |
| `{秒數} 秒內畫面重新讀取了一次整份看板` | `秒數`：整數。 | 不支援 | 無 | `必查`：從 When 送出的時刻起算該秒數內，這個分頁送出至少一次 `getDeskBoard` 請求。 |
| `畫面沒有每 {秒數} 秒定時讀取整份看板` | `秒數`：整數。 | 不支援 | 無 | 連線正常時，帶卡片的訊號由畫面直接換上或拿掉那一張；只有沒帶卡片的訊號、發現中間漏了訊號、`resync`、連線恢復、營業日換了時才重讀整份看板，不會定時重讀。`必查`：把瀏覽器時鐘再往後推 3 個該秒數、期間不送任何即時訊號，這個分頁沒有送出新的 `getDeskBoard` 請求。 |
