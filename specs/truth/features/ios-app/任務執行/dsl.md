# 任務執行 DSL（iOS App）

這個模組的專屬句型。跨模組共用句型見 [`../dsl.md`](../dsl.md)。

## Given 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | App 實作語意（Appium） |
| --- | --- | --- | --- | --- |
| `"{任務}" 已中斷 {分鐘} 分鐘` | `任務`：字串；房號。<br>`分鐘`：整數。 | 不支援 | 無 | `怎麼做`：把這張單的中斷事件與任務時間戳整批往前推該分鐘數，裝置與後端的時鐘都不動。撥時鐘做不到這件事：撥裝置時鐘只動得到 App 那一邊，後端的恢復端點寫起算時刻用的是後端自己的系統時鐘，恢復之後中斷的那一段會整段被算成已做時間；注入值還是固定的一個時刻，畫面上的計時也就停住，驗不出「計時正在走」。`權威狀態落地`：目前時刻離中斷事件已過該分鐘數；`worked_sec` 與 `segment_started_at` 不變。語意同後端 `任務執行` 模組的同名句型，這裡是 App 側的落地方式（兩邊各自是自己介面的權威位置）。 |
| `"{員工}" 已在離線時完成 "{任務}"，這一筆還押在手機上` | `員工`：字串。<br>`任務`：字串；房號。 | 不支援 | 無 | `怎麼做`：把裝置切到無網路，以該員工身分打開該任務的任務頁並點主按鈕「完成」，停在完成畫面。`權威狀態落地`：App 本機佇列有這筆完成動作；**後端該任務狀態還沒有改變**（與 `"{員工}" 剛在 App 完成 "{任務}"，完成畫面停在畫面上` 的差別就在這裡，不可互換）。`回寫`：完成畫面內容與本機佇列筆數。 |
| `"{員工}" 剛在 App 完成 "{任務}"，完成畫面停在畫面上` | `員工`：字串。<br>`任務`：字串；房號。 | 不支援 | 無 | `怎麼做`：以該員工身分登入，打開該任務的任務頁並點主按鈕「完成」，停在完成畫面不再操作。`權威狀態落地`：後端該任務已依 `tasksComplete` 語意轉為 done 或 inspected。`回寫`：完成畫面內容與 `tasksComplete` 回應的 `nextStep`。用於驗「從完成畫面再往下走」的情境——那一步才是受測動作，完成本身降為前置狀態。 |
| `飯店關閉了完成慶祝的氣氛呈現` | 無 | 不支援 | 無 | `怎麼做`：透過後端測試資料把租戶設定 `completion_celebration_enabled` 設為 false。`權威狀態落地`：`tenant_config` 該鍵為 false；`tasksComplete` 回應的 `celebrationEnabled` 為 false。這一鍵只關氣氛，不關接力——接續去向與今日進度的計算不受它影響。 |
| `"{員工}" 已在 App 跳過 "{任務}" 的 SOP 項 "{項目}"` | `員工`：字串。<br>`任務`：字串；房號。<br>`項目`：字串。 | 不支援 | 無 | `怎麼做`：透過後端測試資料（或先執行一次等效的跳過操作）把該 SOP 項標記為 skipped，App 以該員工身分登入後停在該任務頁。`權威狀態落地`：後端 `task_sop_checks` 該項為 skipped。 |
| `"{員工}" 已在 App 打開 "{任務}" 的任務頁` | `員工`：字串。<br>`任務`：字串；房號。 | 不支援 | 無 | `怎麼做`：以該員工身分登入，從首頁點該房的任務卡進入任務頁，停在任務頁。這是 Arrange——給「畫面已開著、世界在背後改變」的情境鋪底；開頁本身是受測動作時用同名的 When。`回寫`：畫面停在任務頁。 |
| `"{任務}" 剛被主管改派給別人，"{員工}" 的畫面還沒更新` | `任務`：字串；房號。<br>`員工`：字串。 | 不支援 | 無 | `怎麼做`：另建一位同部門員工，以主管身分呼叫 `tasksReassign`（`POST /tasks/{id}/reassign`）把該任務改派過去；不點開任何推播、不觸發畫面刷新。`權威狀態落地`：後端該任務的 `assignee_id` 已換人、狀態不變；原本那位員工的畫面仍停在改派前的內容。與同表的「剛被主管作廢」是兩件事：作廢把任務轉 cancelled，改派只換負責人。 |
| `"{任務}" 剛被主管作廢，"{員工}" 的畫面還沒更新` | `任務`：字串；房號。<br>`員工`：字串。 | 不支援 | 無 | `怎麼做`：在該員工的任務頁已開著之後，透過後端測試資料（或等效的主管作廢操作）把該任務轉為已取消；不點開任何推播、不觸發畫面刷新。`權威狀態落地`：後端該任務 cancelled（`cancel_reason`=manager_void），該員工畫面仍停在作廢前的任務頁。 |

## When 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | App 實作語意（Appium） |
| --- | --- | --- | --- | --- |
| `"{員工}" 在 App 跳過 "{任務}" 的 SOP 項 "{項目}"` | `員工`：字串。<br>`任務`：字串；房號。<br>`項目`：字串。 | 不支援 | 無 | `怎麼做`：在任務頁 SOP 清單點該項的「跳過」。`權威狀態落地`：後端 `tasksSopCheck`（`POST /tasks/{id}/sop-check`，result=skipped）成功，`task_sop_checks` 該項為 skipped；不會阻擋後續完成操作。`回寫`：SOP 清單畫面。 |
| `"{員工}" 在 App 恢復 "{任務}"` | `員工`：字串。<br>`任務`：字串；房號。 | 不支援 | 無 | `怎麼做`：在任務頁點置底主按鈕「恢復處理」。`權威狀態落地`：成功時後端 `tasksResume`（`POST /tasks/{id}/resume`）語意落地——interrupted 轉為 doing、`worked_sec` 保留、`hold_reason` 清空；手上已有另一筆 doing 時後端回 409 `doing_task_exists`，畫面出現提示且後端不變；離線時擋在送出之前，不進離線佇列、後端不變。`回寫`：任務頁內容與畫面提示。**這一句要真的按下那顆按鈕**，不是只檢查按鈕文字——按鈕文字由 `任務頁只顯示一個主按鈕，文字為 "{按鈕文字}"` 另外驗。 |
| `"{員工}" 在 App 從完成畫面前往下一步` | `員工`：字串。 | 不支援 | 無 | `怎麼做`：在完成畫面點實心主按鈕（下一間、回到某一間或去待認領，依 `tasksComplete` 回應的 `nextStep.kind` 而定）。`權威狀態落地`：不改任何後端狀態，只換畫面。`回寫`：換頁後停在的畫面。 |
| `"{員工}" 在 App 從完成畫面回到首頁` | `員工`：字串。 | 不支援 | 無 | `怎麼做`：在完成畫面點底部的文字按鈕「回到首頁」。`權威狀態落地`：不改任何後端狀態。`回寫`：換頁後停在的畫面。 |
| `過了 {分鐘} 分鐘` | `分鐘`：整數。 | 不支援 | 無 | `怎麼做`：把裝置時間與後端 `Clock` 一起往前撥該分鐘數，畫面保持開著、不做任何操作。`權威狀態落地`：無——時間流逝本身不產生任何後端事件。`回寫`：畫面上的計時與超時提示。 |
| `"{員工}" 在 App 為 "{任務}" 選擇延後原因 "{原因}" 並確認` | `員工`：字串。<br>`任務`：字串；房號。<br>`原因`：字串；請勿打擾、住客還在房內、先處理別的單。 | 不支援 | 無 | `怎麼做`：在任務頁點「延後」開啟延後面板，點該預設原因（點下去就送出，面板上沒有確認鈕）。`權威狀態落地`：等同後端 `tasksDefer` 語意，`hold_reason`＝該原因文字，`deferred_by_self`=true。`回寫`：任務頁。 |
| `"{員工}" 在 App 為 "{任務}" 選擇中斷原因 "{原因}" 並確認` | `員工`：字串。<br>`任務`：字串；房號或工務單號。<br>`原因`：字串；房務：缺備品，去拿、住客回房、臨時被叫去支援（「需要工務協助」不送原因，見下一列）；工務：等零件、需要外包廠商、住客在房約時間、先處理別的急件。 | 不支援 | 無 | `怎麼做`：在任務頁（房務任務）或工務單詳情（工務單）點「中斷」開啟中斷面板，點該預設原因（點下去就送出，面板上沒有確認鈕）。`權威狀態落地`：等同後端 `tasksInterrupt` 語意，`hold_reason`＝該原因文字；對工務單操作時任務識別為工務單號。`回寫`：任務頁或工務單詳情。 |
| `"{員工}" 在 App 為 "{任務}" 的中斷面板選「需要工務協助」` | `員工`：字串。<br>`任務`：字串；房號。 | 不支援 | 無 | `怎麼做`：在任務頁點「中斷」開啟中斷面板，點「需要工務協助」；這一列不送原因，面板原地換成工務單表單。`權威狀態落地`：這一步不動後端，原任務要等表單送出時（`createRepairTicket` 帶 `interruptSourceTask`=true）才轉為 interrupted。`回寫`：畫面上的面板內容。 |
| `"{員工}" 在 App 為 "{任務}" 選擇延後原因「其他原因」，填入 "{說明}" 並確認` | `員工`：字串。<br>`任務`：字串；房號。<br>`說明`：字串；60 字以內。 | 不支援 | 無 | `怎麼做`：在延後面板點「其他原因」，輸入該說明文字，點確認。`權威狀態落地`：等同後端 `tasksDefer`，`hold_reason`＝該說明文字。`回寫`：任務頁。 |
| `"{員工}" 在 App 為 "{任務}" 的延後面板選「其他原因」並輸入 {字數} 字的說明` | `員工`：字串。<br>`任務`：字串；房號。<br>`字數`：整數。 | 不支援 | `說明內容`：重複「住」字到指定字數。 | `怎麼做`：在延後面板點「其他原因」，輸入指定字數的說明文字，不點確認。`回寫`：延後面板目前的送出鈕狀態與字數提示。 |

## Then 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | App 實作語意（Appium） |
| --- | --- | --- | --- | --- |
| `任務頁顯示已做 {分鐘} 分鐘，且計時正在走` | `分鐘`：整數。 | 不支援 | 無 | `必查`：任務頁的已做時間顯示該分鐘數——顯示值要等於後端的已做分鐘，**正在跑的這一段只能算一次**（秒級公式以契約 `accumulatedSeconds + (現在 − segmentStartedAt)` 為準，不得拿 `elapsedMinutes` 當基準再加本段，那會把本段重複累計）；等待一段時間後數字會往上跳。後端 `tasks.state` 為 doing 且 `segment_started_at` 有值。恢復情境下中斷期間不計入，數字從中斷前的累計接著走，不是從零重新起算。 |
| `"{任務}" 的面板換成工務單表單，原任務還沒有被中斷` | `任務`：字串；房號。 | 不支援 | 無 | `必查`：中斷面板原地換成工務單表單（`repair` 前綴的報修元件可見，中斷原因清單不見），沒有換頁；後端該任務仍為 doing、沒有 `interrupted` 事件、沒有新的工務單。 |
| `任務頁不再顯示停住原因` | 無 | 不支援 | 無 | `必查`：任務頁上沒有停住原因那一塊；後端 `tasks.hold_reason` 為 NULL。用於恢復之後——那張單已經接回來做了，停住原因留著會讓員工看著一個已經不成立的理由繼續做。 |
| `任務頁顯示已做 {分鐘} 分鐘，且計時沒有在走` | `分鐘`：整數。 | 不支援 | 無 | `必查`：任務頁的已做時間顯示該分鐘數；等待一段時間後數字不變。後端累計時間一致。 |
| `完成被擋下，畫面顯示後端拒絕的原因` | 無 | 不支援 | 無 | `必查`：畫面出現提示（Alert，比照 `task.busy-alert` 的語意），文字就是後端這次 4xx 回應的 message——App 不自己湊文案；不進完成畫面、任務沒被標成完成；後端該任務維持被拒前的狀態（沒有新的 completed 事件）。禁止無聲：提示沒有出現就算失敗，即使後端狀態正確。 |
| `任務頁顯示打掃步驟條，目前停在 "{步驟}"` | `步驟`：字串；已接、進行中、完成、查房、免查房。 | 不支援 | 無 | `必查`：以 accessibility id `task.step-track` 定位，打掃類步驟條（已接→進行中→完成→查房／免查房）目前標示的步驟與後端 `tasks.state`／`inspection` 對照一致。 |
| `任務頁顯示備品步驟條，目前停在 "{步驟}"` | `步驟`：字串；已接、進行中、送達。 | 不支援 | 無 | `必查`：以 accessibility id `task.step-track` 定位，備品類步驟條（已接→進行中→送達）目前標示的步驟與後端 `tasks.state` 對照一致。 |
| `任務頁只顯示一個主按鈕，文字為 "{按鈕文字}"` | `按鈕文字`：字串；開始、完成、延後、恢復處理。 | 不支援 | 無 | `必查`：以 accessibility id `task.primary-button` 定位，畫面上只有一個置底主按鈕，文字與目前狀態對照表相符（待開始／本人延後＝開始，進行中＝完成，已中斷＝恢復處理）；延後／中斷是次要按鈕，不算在此主按鈕判定內。 |
| `"{任務}" 的 SOP 進度顯示 "{關鍵字}"` | `任務`：字串；房號。<br>`關鍵字`：字串；如 `跳過不擋流程`。 | 不支援 | 無 | `必查`：任務頁 SOP 進度文字（`x / y · 跳過不擋流程`）包含該關鍵字；勾選與跳過都計入 x，`y` 為 SOP 總項數。 |
| `任務頁顯示 "{超時文字}"` | `超時文字`：字串；如 `超時 5 分`。 | 不支援 | 無 | `必查`：任務頁計時 hero 區顯示該文字；超時分鐘數＝**目前**已做分鐘數減去 `預估分鐘`——畫面開著不操作時要隨時間跟著變大，不是停在進頁或上次向後端取資料那一刻；只在超過時顯示，純提示不觸發推播。 |
| `完成畫面顯示這次用時 {分鐘} 分、當初預估 {分鐘2} 分` | `分鐘`：整數；這次實際用時。<br>`分鐘2`：整數；預估分鐘數。 | 不支援 | 無 | `必查`：完成畫面（accessibility id `celebrate.title` 所在畫面）同一處顯示的實際與預估分鐘數，與後端 `tasks.worked_sec` 換算分鐘、`預估分鐘` 一致；實際是主要數字、預估是附註，兩者不是同一級。 |
| `完成畫面只顯示這次用時 {分鐘} 分` | `分鐘`：整數。 | 不支援 | 無 | `必查`：完成畫面顯示該用時，且畫面上沒有預估欄位——不是顯示成空白或 0，是整個欄位不存在。用於沒有預估分鐘的任務。 |
| `完成畫面的標題帶出房號 "{房號}"` | `房號`：字串。 | 不支援 | 無 | `必查`：以 accessibility id `celebrate.title` 定位，標題文字包含該房號，且房號與這次完成的那一張任務一致。 |
| `完成畫面說明 "{說明}"` | `說明`：字串。 | 不支援 | 無 | `必查`：完成畫面標題下方的說明文字等於該文字。三種說法由這次完成的任務決定：鎖定免查房的打掃＝免查房、直接完成；需查房的打掃＝已通知主管查房；其他類別＝住客會收到完成通知。與後端 `tasks.type`／`inspection_waived` 對照一致。 |
| `完成畫面的下一步指向 "{房號}"` | `房號`：字串。 | 不支援 | 無 | `必查`：完成畫面的實心主按鈕文字包含該房號，且與 `tasksComplete` 回應的 `nextStep.roomNo` 一致。按鈕按下去會開啟那一間的任務頁。 |
| `完成畫面提示今天排定的房都清完了，下一步是去待認領` | 無 | 不支援 | 無 | `必查`：完成畫面出現「都清完了」的提示句與前往待認領的實心主按鈕，且 `tasksComplete` 回應的 `nextStep.kind` 為 `all_clear`。這一條必須與「下一步指向某房號」在畫面上可分辨——不可只是主按鈕消失。 |
| `完成畫面顯示今日進度為第 {單數} 單` | `單數`：整數。 | 不支援 | 無 | `必查`：完成畫面的今日進度磚顯示該單數，與 `tasksComplete` 回應的 `cleaningDoneToday` 一致；同一時刻首頁「已清完間數」的分子也是同一個數字。 |
| `完成畫面不顯示今日進度` | 無 | 不支援 | 無 | `必查`：完成畫面上沒有今日進度那一塊——整塊不存在，不是顯示 0 或空白。用於備品等非打掃類任務，以及氣氛呈現被關閉時。 |
| `完成畫面說明這一筆還沒送出` | 無 | 不支援 | 無 | `必查`：完成畫面出現「已先記錄在手機、恢復連線後自動送出」意思的說明文字；後端該任務狀態尚未改變，App 本機佇列有這筆完成動作。 |
| `完成畫面蓋在 "{任務}" 的任務頁上` | `任務`：字串；房號。 | 不支援 | 無 | `必查`：完成畫面是疊在剛完成的那張任務頁之上的半透明覆蓋層，遮罩底下那一頁的房號仍然看得到。**不可只檢查完成畫面存在**——把半透明遮罩推上不透明路由時完成畫面一樣存在，但底下是一片黑，這一條要擋的就是那個。 |
