# 自己打開 App 點一點：從零到登入

寫給第一次操作的人。照著從上到下做就會跑起來，不需要先懂 Flutter、Appium 或
Docker。每一段都寫了「這一步在做什麼」，出錯時比較知道要看哪裡。

整件事只有三塊：資料庫與後端要先活著、資料庫裡要有看得到的資料、App 要裝進
iPhone 模擬器。照順序做一次大約十分鐘，之後再開只要重做第 4、5 步。

全部指令都在專案根目錄 `~/IdeaProjects/tms-mvp` 底下執行。

---

## 1. 起資料庫

資料庫跑在 Docker 裡。開一個終端機視窗：

```bash
cd ~/IdeaProjects/tms-mvp
docker compose up -d
```

確認它真的起來了（看到 `tms` 的那一列是 running 就對了）：

```bash
docker compose ps
```

> Docker Desktop 沒開的話這一步會失敗，先去開 Docker Desktop 再回來。

---

## 2. 起後端

後端是一支 Java 服務，聽 8080 埠。它要一直開著，所以**開一個新的終端機分頁**跑：

```bash
cd ~/IdeaProjects/tms-mvp
TMS_DB_URL=jdbc:postgresql://localhost:5433/tms \
JAVA_HOME="$(/usr/libexec/java_home -v 25)" \
./tms/mvnw -f tms/pom.xml spring-boot:run
```

看到一行 `Started TmsApplication in ...` 就代表起好了。這個視窗不要關。

想確認它活著，在**另一個**視窗打：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/api/v1/pool
```

印出 `401` 就是正常的——沒帶登入權杖本來就該被擋，重點是它有回應。印出 `000`
代表後端還沒起來。

---

## 3. 種示範資料

資料庫剛起來是空的，直接登入會看到一片空白。跑這支腳本把示範資料種進去：

```bash
cd ~/IdeaProjects/tms-mvp
./scripts/seed-demo.sh
```

它會印出清點結果（員工 6 位、房間 18 間、任務 24 張、工務單 9 張、通知 17 則）。

**這支腳本可以重複跑**，跑幾次結果都一樣——它每次都先把自己上次種的那一份刪掉
再重種。什麼時候要重跑：

- 畫面上的資料不見了、變成空白（多半是有人跑了 `app/bdd` 的自動化測試，那個東西
  每個情境開場都會把資料庫清空）；
- 跨過午夜之後——資料裡的「今天」是以執行當下算的，隔天要玩就重跑一次。

---

## 4. 把 App 裝進模擬器

第一次要編譯，大概要等三到五分鐘。

```bash
cd ~/IdeaProjects/tms-mvp/app/mobile
flutter run -d 79F32D5C-7A71-47D6-AA8D-8142E68CFF48
```

那一長串是 iPhone 17 模擬器的編號。模擬器沒開的話這道指令會自己把它開起來，
編譯完也會自動把 App 裝好並打開。這個視窗一樣不要關——關掉 App 就會被中止。
在這個視窗按 `r` 可以熱重載、按 `q` 離開。

> 不確定有哪些模擬器可以用：`xcrun simctl list devices available`。
> 換一顆就把上面那串編號換掉。

**另一條路（不想讓終端機被佔著）**：先自己編譯、安裝、啟動，之後 App 就留在
模擬器裡，隨時點圖示就能開。

```bash
cd ~/IdeaProjects/tms-mvp/app/mobile
flutter build ios --simulator --debug

UDID=79F32D5C-7A71-47D6-AA8D-8142E68CFF48
xcrun simctl boot "$UDID" 2>/dev/null; open -a Simulator
xcrun simctl install "$UDID" build/ios/iphonesimulator/Runner.app
xcrun simctl launch "$UDID" com.athena.tms.tmsStaffApp
```

> 模擬器裡如果跳出中文注音鍵盤蓋住輸入框，在模擬器選單列選
> `I/O → Keyboard → Connect Hardware Keyboard`，之後就能直接用電腦鍵盤打字。

## 5. 登入

三組帳號，密碼都是 `demo1234`：

| 員工編號 | 密碼 | 是誰 | 登入後會到哪 |
|---|---|---|---|
| `hk1` | `demo1234` | 小美，房務員工 | 房務首頁 |
| `mt1` | `demo1234` | 阿強，工務員工 | 工務首頁 |
| `mg1` | `demo1234` | 王主管，主管 | 房務首頁（主管沒有部門） |

**要換帳號看，把 App 關掉再打開就好**——登入狀態只存在記憶體裡，重開就回到登入
畫面。在模擬器裡從下緣往上滑把 App 滑掉，或用指令：

```bash
UDID=79F32D5C-7A71-47D6-AA8D-8142E68CFF48
xcrun simctl terminate "$UDID" com.athena.tms.tmsStaffApp
xcrun simctl launch   "$UDID" com.athena.tms.tmsStaffApp
```

不要從「我的」頁面按登出：示範資料刻意讓每個人手上都掛著沒做完的單，而產品規則
是手上有未完成的單就不給登出，按下去只會跳「無法登出」。那是正確行為，不是壞掉。

## 6. 每個畫面建議看什麼

### 用 hk1（小美）登入——房務視角

**首頁**
- 上方問候列會寫「早班」與「3 樓」，那是今天的排班。
- 進度環顯示 3/6：今天六間打掃單，做完三間。
- 最上面那張大卡是「302 退房打掃」，正在進行中，會跑計時（約 18 分鐘起跳）與
  步驟條（六項打掃步驟做了三項、跳過一項）。
- 往下的「我的任務」列表有七張單，每張左邊的狀態標籤顏色不一樣，從上到下涵蓋
  進行中、待開始、已延後、已中斷、待查房、查房通過、完成·免查房。**六種狀態的
  顏色都在這一頁看得到**，這是這次要看的重點之一。

**分頁列（畫面最下方）**
- 「待認領」那一格右上角有紅色 6，代表池子裡有六張可以搶的單。
- 「通知」那一格有紅色 3，代表三則未讀。

**待認領**
- 六張單。上方的分類磚會顯示：全部 6、打掃 2、備品 2、修繕 1、其他 1——
  **四種分類的數字都不是零**。
- 單卡上的彩色標籤刻意鋪開了不同來源：住客掃碼、櫃檯轉單、主管退回、請假退回、
  查房退回、自動化規則各一張。
- 排在最前面的兩張是「未接超時」的（202 與 203），那是超時沒人接被頂上來的。
- 「306 補礦泉水」那張會標「同樓層」，因為小美今天負責 3 樓。
- 點任一張可以試「接單」，接完它就會出現在首頁的我的任務裡。

**任務頁**（從首頁點 302 那張大卡進去）
- 計時與步驟條在上方；六項打掃 SOP 可以勾、可以跳過。
- 往下有「同房工務單」一張：W-0104 書桌椅腳鬆動。
- 再往下有「交辦」兩則，是早班交班留給 302 這間房的話。
- 右上角的「查一下」可以問問題，會引用這間房過去的維修紀錄當出處。

**通知中心**
- 六則通知，左邊的圓形圖示顏色不同：紅色是急件、橘色是超時未接、綠色是完成、
  藍色收件匣是新單、藍色對話框是交辦回覆、灰色是純告知。
- 未讀的三則標題是粗體、右邊有小圓點。點一則會標成已讀並跳到對應的地方，右上角
  有「全部標為已讀」。
- **紫色的「保養」分類看不到**——後端目前沒有保養這種事件，產生不出來，不是
  App 壞了。

**我的**
- 身分卡會顯示「小美／房務」。
- 底下是「通知與顯示」與「帳號」兩組設定，多數項目會跳出「這個設定尚未開放」。
- 原型上身分卡下面還有一排工作統計磚（做了幾間、平均幾分鐘），目前畫面上沒有
  這一塊，後端也沒有對應的資料（見最後一節）。

## 7. 出問題時

| 現象 | 多半是什麼 | 怎麼辦 |
|---|---|---|
| 登入時說「無法連線到伺服器」 | 後端沒起來 | 回第 2 步，確認那個視窗還開著 |
| 登入成功但每一頁都空白 | 資料被清掉了 | 重跑第 3 步的 `./scripts/seed-demo.sh`，再把 App 下拉重新整理 |
| 帳號密碼打對卻說錯誤 | 連續打錯五次會鎖 15 分鐘 | 等 15 分鐘，或重跑種子腳本（會把帳號重建） |
| 單上的時間怪怪的、今天的單不見了 | 跨過午夜了 | 重跑種子腳本 |
| `flutter run` 報錯找不到裝置 | 模擬器編號不對 | `xcrun simctl list devices available` 換一顆 |

## 8. 這次看不到的東西（資料面本來就沒有，不是 App 漏做）

這兩塊是刻意留白的，後端目前沒有資料來源，硬塞假資料只會讓人誤以為功能已經有了：

- **「我的」頁面的工作統計磚**（做了幾間、平均幾分鐘那一類）——後端沒有這支
  查詢，App 也還沒畫這一塊，所以身分卡底下直接就是設定清單。
- **工務首頁的「今日保養」那一格**——保養維度後端回的是空值，那一格因此不會畫
  出來。同理，通知中心的紫色「保養」分類圖示也出不來，十七種推播事件裡沒有保養
  專屬的那一種。

另外，主管（mg1）的「待認領」徽章永遠是 0：主管帳號不屬於任何部門，系統不知道
要幫他數哪一池的單，這是設計如此。
