# App 設計系統規格（從原型抽出）

這份文件是 App 視覺實作輪的輸入。所有數值都從 `specs/plans/001-staff-app-increment/ui/prototype/Main.dc.html`
實讀抽出，每一條都附原型行號。看不到行號的數值就是我沒查到，不要照抄。

原型第 2 行有一整塊 `<style data-dc-design-system-vars>`，裡面是 Claude Design 匯出的
完整 token 定義（品牌色、iOS 系統色、間距階梯、圓角階梯、字級階梯）。那是這份規格的根；
底下每一節都是「token 定義 + 原型實際怎麼用它」兩層。

### 2.2 縮放怎麼運作

- 原型用 CSS `zoom` 模擬：`.tms-zoom > *:not(.tms-nozoom){zoom:var(--tz,1)}`（`Main.dc.html:39`），
  `--tz` 由 `ui.tz` 餵入（`75`、`1164`、`1711`、`1768`、`1923`、`2058`）。
- `ui.tz` 的算法在 `4446`：七段字級 `[14,15,16,17,19,21,23]`，除以基準 17 得縮放比，
  預設第 4 段（index 3，= 17 ⇒ 1.000）。七段比值依序 **0.824 / 0.882 / 0.941 / 1.000 / 1.118 / 1.235 / 1.353**。
- **不縮放的東西**：導覽列與「文字大小」設定頁本身掛 `.tms-nozoom`（`106`、`518`）。
- 捲動容器的 padding 用 `calc(16px / {{ui.tz}})` 反除（`1164`），讓**間距不跟著放大**——
  原型自己也寫明了：「正式版用 Dynamic Type 只放大文字，不放大間距與圖示」（`125`、`856`）。

**Flutter 做法**：七段對應 iOS Dynamic Type 的 Body 字級（xS 14 / S 15 / M 16 / L 17 標準 /
xL 19 / xxL 21 / xxxL 23，見 `496-497` 的註解）。用
`MediaQuery.withClampedTextScaling(minScaleFactor: 0.824, maxScaleFactor: 1.353)` 包住 App，
字級全部用 `TextStyle(fontSize: …)` 由 textScaler 處理；**所有 `EdgeInsets` / `SizedBox` /
圖示尺寸一律寫死 logical pixel，不乘 textScaler**。這個設定只改 TMS 自己，不改整支手機。

## 7. 實作輪建議怎麼切

**不要「先建 theme 再逐畫面」，也不要「先做共用元件再逐畫面」——這兩個都會卡住。**
原因：theme 單獨做沒有驗收點（BDD 不測顏色），共用元件單獨做沒有使用現場（規格會長歪）。

建議三段：

**第 1 段 — token ＋ 一支示範畫面（約 2 天）**
先把 §1–§3 落成 `TmsColors` / `TmsTypography` / `TmsSpacing`（放 `core/theme.dart`，
`CupertinoThemeData` ＋ `ThemeExtension`），**同時**把落差 #5（callout 四色）與落差 #16（連線狀態列）
做完——這兩項改動小、跨三個畫面、能立刻驗證 token 是否好用。做完這段，`CupertinoColors.activeBlue`
應該在整個 repo 歸零。

**第 2 段 — 共用元件庫（約 3 天）**
在 `lib/core/widgets/` 建八個元件，每個都照 §4 的規格，並且**同一個元件同時被房務與工務使用**
（這是防止再長出第五套卡片的唯一辦法）：
`TmsCard`（主卡 20 ／ 群組 16 兩種）、`TmsStatusChip`（吃 §4.3 的狀態表）、`TmsCallout`（六語氣）、
`TmsPrimaryButton` / `TmsSecondaryButton`、`TmsStepper`（房務三／四步與工務四步共用）、
`TmsEmptyState`（置中型／卡片型）、`TmsGroupedList`（＋`TmsGroupedRow`）、`TmsCategoryTile`。
順手把落差排名裡「跨畫面的重複實作」那四套卡片、四套 chip 收掉。

**第 3 段 — 逐畫面套用，按落差排名由大到小**
Tab bar（#3）必須排在首頁（#2）之前，因為它改變首頁的導航責任。之後
首頁 → 任務頁 → 待認領 → 我的 → 通知 → 慶祝 → 三個面板 → 工務三支 → 登入。
工務三支（#14/#15/#18）排最後，因為第 2 段的元件若真的做對，它們幾乎只剩接線。

**驗收**：現有 BDD 全綠是硬門檻，每段結束跑一次。視覺本身 BDD 驗不到，
每支畫面改完請用模擬器截圖，與原型對應行號的區塊並排比對。

**兩個先問清楚再動的點**：矛盾 ① 的狀態列底色，以及 §5 末尾「原型沒有」的兩項。
在拿到裁決前，狀態列先走 TONE 表的彩色淡底，那兩項先不做畫面。

## 裁決一：callout 底色以原型實際呈現為準

原型 `Main.dc.html:1231-1234` 的註解寫「iOS 不用彩色底色卡表達嚴重度」，但同一個節點實際吃的是 TONE 表的彩色淡底。**以實際呈現為準，採彩色淡底**；註解那句不實作。依據是 TONE 表被房務與工務兩側共同引用、是唯一真實來源，而註解沒有對應的實作落地。本規格其餘五處原型內部矛盾，同樣一律以「原型實際渲染出來的樣子」為準。

### 取捨

問候區日期行 +2pt、問候語 −7pt，整體約少 5pt；列表每列約 +4pt（副標 13→15），首頁約少顯示半列。換來的是第一線邊走邊看、戴手套單手操作時更好讀——房務常見年齡層偏高，13pt 灰字在走廊燈光下辨識度低。數字與房號大小不變；問候語縮小後，視覺重點從「早安」移到「今天的進度」與「下一間 305」。

### 工程注意

- 字級以 iOS Text Style 實作（問候語 `Font.title.bold()`、日期 `.subheadline`…），**不要寫死 pt**；「我的 › 文字大小」以 Dynamic Type 等比放大。問候語在最大字級時約 40pt，仍可完整顯示不被截斷。
- 最大字級（AX1 以上）時，進度卡改為上下排列（環在上、數字在下），列表副標允許兩行。
- 房號與計時器使用等寬數字（`tabular-nums`）。

### 實作順序

先改兩處影響最大的：日期 · 班別 · 樓層 15pt、列表標題 15pt；其餘字重統一可在同一次調整一起完成。**工務端沿用同一套層級。**
