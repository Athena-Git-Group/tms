- **原型來源**：TMS 房務工務 App 原型（canvas.json 便利貼、Main.dc.html 房務／工務手機 App、Desk.dc.html 櫃檯 iPad App）

## 總結與優先建議

1. **工務（修繕）端幾乎整塊缺口**：審核流程（X1）、急件（X2）、照片（X3）、完修/驗收（X4）、自開單與公共區域（X8）、與打掃任務的關聯（X9）——spec 目前把修繕當成「和備品一樣的簡單任務」，與原型差距最大，建議獨立成章。
2. **查房策略矛盾要先拍板**（X5）：原型明確要求 inspection 三值（passed/waived/failed）與「續住清免查房」開關，和 spec「打掃一律查房→inspected」直接衝突，影響狀態機、PMS 回寫與報表口徑。
3. **延後/中斷語意**（Y1）是現有章節中行為不一致最嚴重的一處：觸發者（本人 vs 主管）、單的歸屬（留名下 vs 回池）、恢復路徑都不同。
4. 通知中心與推播偏好（X10）、代開單（X7）、遺失物擴充（Y3）是端點清單要直接增補的三塊。
