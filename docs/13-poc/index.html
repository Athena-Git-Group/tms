租戶設定 並排展演模式 事件流水帳
互動 POC · 五視角

一支掃碼需求，怎麼變成一間查驗合格的房間

這是一個分角色的產品原型：住客在手機上提需求、櫃檯判讀分流、房務搶單處理、 主管查房把關、老闆遠端看數字——五個視角共用同一套瀏覽器端模擬任務引擎，跨分頁即時連動。

與 05 派單沙盤的差異：那份是單頁可切換的沙盤模擬器；這裡是分角色的獨立產品頁面， 狀態一律採九態正式命名（triage / pool / accepted / doing / done / inspected / deferred / interrupted / cancelled），不用沙盤裡的簡化命名。

五個視角，請各開一個分頁

建議依序開啟：住客 → 櫃檯 → 房務（可留主管分頁備用），操作後互相切換就能看到即時連動。 只有一個螢幕的話，改用右上角的「並排展演模式」，三個視角同畫面連動。 住客頁顯示的資訊、需求選單與流程規則（例如打掃要不要查房）都能在「租戶設定」即時調整。

2 則唯讀故事 開啟老闆頁（新分頁）

這個 POC 刻意沒做的部分

範圍外清單——略過的理由寫在旁邊，不是忘了做。

  • 交班單檢視簽收 跨班次狀態在單一 demo session 裡很難自然展示，而且不在「掃碼→查房」這條黃金路徑上。
  • 主管的請假退池／工時缺口試算 功能範圍大，且不是這次要展演的黃金路徑；排房與查房已覆蓋主管視角的核心戲碼。
  • 排房的拖曳操作與真 .xlsx 解析 改派用下拉選單就能演完故事，拖曳是互動糖衣；Excel 匯入以 CSV 文字示意，真 .xlsx 要再拉解析庫，留正式版。
  • 租戶設定的其餘可調項 已做：資訊頁、需求選單（含自建項目）、流程開關、標準工時、SLA 時限、班次容量、SOP／查房項目、自動分配策略、老闆通知門檻。留給正式版：多語內容、責任區與 VIP 排序、顯示層自訂（狀態改名、語意類別下加子狀態）。
  • 老闆通知的「主管手動上報」來源 老闆頁的出事通知 v1 有兩個來源：住客評低分、主管手動上報。這裡示範前者（評 2 星以下自動出現），後者需要在主管端加上報流程，不在這條黃金路徑上。
