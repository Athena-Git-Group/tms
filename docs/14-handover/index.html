TMS 交接手冊

這一頁 3 分鐘讀完：系統長什麼樣、你該先讀哪一頁、交接前最要緊的幾件事。細節都在後面六頁，照你手上的任務挑著讀就好。

這份交接給誰？讀完能做什麼？

重點

給接手這個 repo 的工程師。讀完能在自己的 Mac 上把三條驗收測試跑起來、知道新增一個測試場景要改哪幾個檔，並看懂員工 App 與 Java 後端怎麼組起來、哪裡會咬人。

這裡只講「程式怎麼跑、測試怎麼跑、會在哪裡卡住」。需求以 specs/truth/features/ 的可執行規格為準，資料表以 tms/src/main/resources/db/migration/ 的 Flyway 遷移檔為準；docs/ 底下 11、12、13 等開發前的設計稿沒有跟著程式碼更新，不要拿來當依據。

整個系統長什麼樣？

重點

一個 Java 後端，前面接員工 App 與櫃檯／住客網頁，後面接 Postgres 與 Kafka。規格只寫一份，三條驗收測試直接讀它去操作 App、網頁與後端。

我手上有一件事，該從哪頁讀起？

重點

不用從頭讀到尾。挑最像你今天任務的那一欄，照順序讀；每一欄都不超過三頁。

各頁在講什麼、要讀多久？

重點

六頁各自獨立，每頁 10 分鐘內讀完；查表型的細節都收在可展開的區塊裡，需要時再打開。

第一天裝機清單、repo 地圖、三套環境與 port 總表。約 8 分鐘 本機手測起手動環境、掃房間 QR，從住客、櫃檯、員工 App、主管一路點回住客。約 7 分鐘 BDD 測試規格怎麼變成三條可執行的驗收測試，每條怎麼跑、怎麼加場景。約 10 分鐘 Flutter App三種殼一套程式、自刻的狀態與路由、網路層、推播、測試約定。約 8 分鐘 Java 後端版本與相依、模組、多飯店隔離、登入授權、資料庫遷移。約 9 分鐘 坑與待查依類別分組的已知坑，以及接手後要先查清楚的事。約 7 分鐘

交接前最要緊的是哪幾件事？

重點

下面五條任何一條沒注意到，都會讓你白白浪費半天，或毀掉別人的資料。

  1. 每條 Java 指令都要切到 JDK 25，後端測試還要帶 -DargLine="-Dapi.version=1.44"。原機器 shell 預設是 17；那個參數是 OrbStack 上跑 Testcontainers 的唯一解法，沒寫進任何設定檔。怎麼確認環境通了
  2. 已知會紅的測試清單在 specs/plans/006-engineering-pool-repair-ticket/implement-notes.md。第一次跑出紅燈，先對照它再懷疑環境。
  3. App 與網頁驗收每個場景都會清空資料庫。兩條線預設共用 8080／5433，不能同時跑；手動操作一律用 8083／tms_manual。三套環境
  4. 既有的 Flyway 遷移檔一個字都不能改，連註解都不行。改了後端就啟動失敗，要修只能新增更高版號的檔。遷移規矩
  5. Android 正式版缺網路權限。INTERNET 只宣告在 debug 與 profile，release APK 會連不上網，是上線前最優先要修的一條。App 還沒補的洞
