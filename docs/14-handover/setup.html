測試、手動、開發三套環境為什麼要隔開？

重點

因為 App 與網頁驗收每個場景都會把資料庫清空。誰跟測試共用資料庫，誰的資料就會無聲消失。所以同一台 Postgres 與 Kafka 拆成互不相干的幾套邏輯環境。

問題很具體：驗收在每個場景開頭都 TRUNCATE（清空整張表）它連到的資料庫，只留 tenants 與 flyway_schema_history。你開著 App 連 8080 手動點，同時有人在跑驗收，剛建的單下一秒就不見，而且沒有任何錯誤訊息。

壞做法大家都連 8080／tms

手動與自動測試互相清掉對方的資料；測試又開著可撥的時鐘，手動操作時看到的「現在」可能是測試撥過的時間。

現在的做法同一台 Postgres 與 Kafka，拆成互不相干的邏輯環境

環境後端資料庫Kafka時鐘用途
開發堆疊／驗收80805433 / tms9092，topic tms.*可撥Web 驗收、App 驗收預設
App 驗收隔離堆疊80815434（tms-bdd-postgres）/ tms9094（tms-bdd-kafka）可撥讓 App 與 Web 驗收同時跑

手動環境選「另開一個 database」而不是「另開一個 schema」，因為 V1__schema.sql:396 把授權寫死在 public schema 上（GRANT USAGE ON SCHEMA public TO tms_app）。

權衡推播消費者的 consumer group 名稱 tms-push-sender 寫死在程式裡，8083 與 8080 會落在同一個 group（各自訂閱不同 topic），任一邊起停時另一邊的推播會停頓幾秒。兩邊的 JWT 預設密鑰也相同，token 可以互通。

App 驗收隔離堆疊目前 repo 裡沒有啟動腳本，見接手待查。

想自己點點看，手動環境怎麼用？

重點

一行 bash scripts/manual-env/up.sh --build --phone --app 就會打包後端、起後端 8083 與網頁 5300、灌示範資料，並把連 8083 的員工 App 裝到 simulator。密碼都是 demo1234。

共用設定在 scripts/manual-env/env.sh。執行檔、pid 與 log 都放在 ~/.tms-manual-env/；啟動時會把 tms/target/tms-0.0.1-SNAPSHOT.jar 複製成 ~/.tms-manual-env/tms-manual.jar 再跑，所以之後重建後端不影響正在跑的手動環境。

# 第一次或程式碼更新後：打包後端 → 起後端與網頁 → 灌資料 → 裝 App
bash scripts/manual-env/up.sh --build --phone --app
bash scripts/manual-env/up.sh --keep-data   # 只重起，保留測到一半的資料（不加參數會重灌＝重置）

四個參數可以自由組合：--build 先用目前程式碼重新打包後端（配 --app 時 App 也重編）、--keep-data 不重灌資料、--phone 讓網頁聽所有網卡（同區網手機才連得進來）、--app 最後把員工 App 裝到 simulator 並打開。

bash scripts/manual-env/status.sh            # 後端、網頁、資料庫、App 各自的狀態與連到哪裡
bash scripts/manual-env/app.sh --no-build    # 沿用上次編好的 App，只重裝並打開
bash scripts/manual-env/app.sh --run         # flutter run 前景執行，改 App 時可 hot reload
bash scripts/manual-env/qr.sh 407 --phone    # 407 房的住客 QR 圖，給手機掃
bash scripts/manual-env/qr.sh --all --phone  # 所有在住房的 QR，加一張可列印總表

App 連哪個後端是編譯時決定的。跑過 App 驗收測試後，simulator 上會換成連 8080／8081 的版本，這時帳密都對也登不進手動環境，重跑 app.sh 就好。產生 QR 圖需要 brew install qrencode；房間要有「現在在住」的訂單，住客頁才進得去。
