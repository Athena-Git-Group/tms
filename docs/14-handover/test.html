本機手測：一個人在自己的 Mac 上把整條流程走一遍

住客掃房間 QR 提出需求，櫃檯在網頁上派單，員工在 App 上做完，主管驗收工務單，最後住客看到「已完成」並評分。這頁教你起環境、用哪些帳號、每一步該看到什麼，以及卡住時怎麼辦。

約 7 分鐘

手動環境是什麼，為什麼不直接用驗收測試的環境？

重點

手動環境是一套專門給人點的後端與網頁：後端 8083、網頁 5300、資料庫 tms_manual。它跟自動驗收測試完全分開，所以你測到一半的資料不會突然消失。

問題出在驗收測試的習慣：每個測試場景開始前，它都會把自己連的資料庫整個清空。你如果拿 App 連驗收用的 8080 後端手動點，同時有人在跑測試，剛建的需求下一秒就不見，而且畫面上沒有任何錯誤。

壞做法手動操作也連驗收測試的 8080／tms

資料會被測試清掉；驗收後端還開著可以撥動的測試時鐘，你看到的「現在」可能是測試撥過的時間。

現在的做法同一台 Postgres 與 Kafka，另開一套邏輯上獨立的環境

手動環境用自己的 database tms_manual、自己的埠號，Kafka 的 topic 全部加上 manual. 前綴，後端用真實時鐘。所有指令都在 scripts/manual-env/，執行檔、pid、log 與 QR 圖都放在 ~/.tms-manual-env/，不放進專案。

權衡兩套環境共用同一台 Postgres 與 Kafka，手動環境起停時，驗收後端的推播會停頓幾秒。完整的環境比較與原因見第一天・三套環境。

怎麼一行把環境起起來？

重點

在專案根目錄跑 bash scripts/manual-env/up.sh --build --phone --app。它會打包後端、起後端與網頁、灌示範資料，最後把員工 App 裝到 iOS 模擬器並打開。

開始前先確認這幾樣工具都在。怎麼安裝見第一天・要裝哪些東西。

第一次用，或程式碼有更新時，跑第一行。環境已經起過、只想重起又不想丟資料，跑第二行。

# 第一次或程式碼更新後：打包後端 → 起後端與網頁 → 灌資料 → 裝 App
bash scripts/manual-env/up.sh --build --phone --app

# 已經起過：重起但保留測到一半的資料與房間 QR
bash scripts/manual-env/up.sh --keep-data --phone --app

跑完它會印出櫃檯網址、住客 QR 的指令，以及新走一遍該用哪些帳號。文中的「模擬器」指 iOS simulator，也就是 Xcode 附的、在 Mac 上跑的虛擬 iPhone；員工 App 就裝在它上面。

不加 --keep-data 就等於重置。不帶參數的 up.sh 會重灌示範資料：你建過的需求全部清掉，每間房的 QR 代碼也換新，之前印出來的 QR 全部失效。

想知道環境現在好不好，跑 status.sh。它只讀不改，會列出後端與網頁有沒有在跑、聽哪個位址，資料庫連不連得上、現在有哪些在住房，以及模擬器上的員工 App 是不是連 8083。

bash scripts/manual-env/status.sh
up.sh 的四個參數 — 可以自由組合
參數作用
--build先用目前的程式碼重新打包後端（跳過測試）；配 --app 時 App 也重新編譯
--keep-data不重灌資料，保留測到一半的資料與房間 QR
--phone網頁聽所有網卡（0.0.0.0），同一個區網的手機才連得進來
--app最後把員工 App 裝到模擬器並打開；沒加 --build、而且上次編好的就是連 8083 的版本時，不重編
其他單獨的指令 — 只重裝 App、重灌資料、單獨起停 
bash scripts/manual-env/app.sh               # 重新編譯員工 App → 裝到模擬器 → 打開
bash scripts/manual-env/app.sh --no-build    # 沿用上次編好的 App，只重裝並打開（幾秒鐘）
bash scripts/manual-env/app.sh --run         # flutter run 前景執行，改 App 程式時可以 hot reload
bash scripts/manual-env/app.sh --device "iPhone Air"   # 指定模擬器（名稱或 UDID）
bash scripts/manual-env/seed.sh              # 重灌示範資料（＝重置，QR 會換新）
bash scripts/manual-env/start.sh             # 起後端＋網頁；已經在跑的會沿用
bash scripts/manual-env/stop.sh              # 全停；資料保留

start.sh 與 stop.sh 都可以只帶 backend 或 web，只動一半。app.sh 會自己挑模擬器：有開機中的 iPhone 就用它，沒有就挑最新 iOS 版本的第一台 iPhone 開機。

要用哪些帳號？

重點

密碼都是 demo1234。新走一遍用 fd1 派單、hk2 做房務、mt2 做工務、mg1 驗收工務單。先不要用 hk1、mt1。

櫃檯網頁的網址裡帶著飯店代碼 demo-hotel，登入頁是 http://localhost:5300/demo-hotel/login。員工 App 登入只填員工編號與密碼，沒有飯店代碼欄位。

帳號角色在哪裡用新走一遍時
fd1櫃檯櫃檯網頁用它派單
hk2房務員工 App用它做房務
mt2工務員工 App用它做工務單
mg1、mg2主管櫃檯網頁、員工 App用來驗收工務單
dm1值班主管櫃檯網頁這條流程用不到
hk1、mt1房務、工務員工 App先不要用

為什麼避開 hk1 與 mt1：示範資料裡他們身上已經各有一件進行中的工作（hk1 在打掃 302、mt1 在修 502），而一個人同時只能做一件，用他們會在「開始」那一步被擋下來。mg1 身上也有一件，但主管驗收不受這個限制，照樣可以驗收。

完整流程怎麼走一遍？

重點

住客送出兩筆需求：一筆設備報修、一筆備品。報修要櫃檯派給工務，工務做完還要主管驗收；備品直接進房務。兩筆都做完，住客頁不用重新整理就會顯示「已完成」。

先確認環境起好了（上一節的 up.sh），再照下面的順序走。幾個名詞先講清楚：「待派單」是櫃檯還沒決定交給誰的需求；「待認領」是已經分到房務或工務、等員工自己接的單；「工務單」是工務維修的單據，要一路追蹤到主管驗收才結案。

  1. 住客送出兩筆需求（住客頁）。跑 bash scripts/manual-env/qr.sh 407 --phone 用手機掃，或跑 bash scripts/manual-env/qr.sh 407 把印出的網址貼到電腦瀏覽器。首頁有「設備報修」與「備品補充」兩張卡片。報修打一句話送出，例如「冷氣不冷」；備品選加毛巾或礦泉水送出。
    該看到的：兩筆需求都出現在住客頁，報修那筆顯示「已送出」。
  2. 櫃檯派單（櫃檯網頁，fd1）。電腦開 http://localhost:5300/demo-hotel/login，用 fd1 登入，看「總覽看板」。報修的文字需求會在「待派單」，就算文字對中「冷氣」這類工務關鍵字也一樣，要櫃檯確認後再派。把它拖到工務。
    該看到的：系統開出一張工務單，卡片上的單號從 T- 開頭變成 W- 開頭，住客頁那筆變成「已受理」。備品那筆不在待派單，已經直接在房務的「待認領」。
  3. 工務做完（員工 App，mt2）。模擬器上的員工 App 用 mt2 登入，在「待認領」找到這張 W- 單。示範資料裡還有其他房間的單，認房號 407 和你打的那句話。依序按認領、開始，最後做完修回報，結果選「已修好」並附照片，模擬器上可以從相簿挑一張。不要選「不需處理」：那個選項會直接結案、不經主管驗收，下一步就沒單可驗。
    該看到的：按下開始後，住客頁即時變成「處理中」；完修回報後這張單等主管驗收，還沒結案。
  4. 主管驗收（員工 App，mg1）。App 登出，改用 mg1 登入，打開「待驗收」，點這張單，按通過。
    該看到的：驗收完這張工務單才算結案。
  5. 房務做完（員工 App，hk2）。App 改用 hk2 登入，在「待認領」認領備品那筆（同樣認房號 407 和品項），依序按開始、完成。
  6. 住客看結果並評分（住客頁）。回到住客頁，不用重新整理。
    該看到的：兩筆都顯示「已完成」。房務那筆可以給星等；工務單驗收結案後不提供評分，這是規格的設計，不是壞掉。櫃檯看板上也看得到兩張單結案。

想重來一次，跑 bash scripts/manual-env/seed.sh（或不加 --keep-data 的 up.sh）把資料重置，再重跑 qr.sh 拿新的 QR。

手機要怎麼掃得到？

重點

手機與 Mac 連同一個 Wi-Fi，網頁要用 --phone 起（聽所有網卡），再用 qr.sh <房號> --phone 產生 QR 圖。示範資料的在住房是 205、306、405、407、508。

網頁預設只聽這台 Mac 自己，手機連不進來。用 up.sh --phone 起的網頁會聽 0.0.0.0，也就是所有網卡；已經用一般模式起了，就再跑一次 up.sh --keep-data --phone，資料不會丟。

bash scripts/manual-env/qr.sh 407 --phone      # 407 房的 QR 圖，存檔並打開，給手機掃
bash scripts/manual-env/qr.sh --all --phone    # 每間在住房各一張，加一份可列印的總表

qr.sh 407 --phone 會抓這台 Mac 的區網 IP（先看 en0，再看 en1），把住客網址 http://<區網 IP>:5300/g/<代碼> 存成 ~/.tms-manual-env/qr-407.png 並打開。網址最後的代碼是那間房專屬的通行碼，住客頁靠它知道你是哪一房。--all --phone 另外產生總表 ~/.tms-manual-env/qr-sheet.html，每間房有房號、QR 與網址，可以直接印出來貼。

只有「現在在住」的房間掃得進去：房間要有一筆沒被取代的訂單，而且入住時間已到、退房時間還沒到。每次重灌資料，所有房間的 QR 代碼都會換新，舊的 QR 圖與總表就失效。

  • macOS 跳出「是否允許 node 接受連入連線」：第一次用 0.0.0.0 起網頁時會問，要按允許。
  • 公司或咖啡店的 Wi-Fi有時會擋裝置之間互連，這時改用手機熱點，讓 Mac 與手機都連上去。
  • 不加 --phone 產生的總表是 localhost 網址，只能在這台 Mac 的瀏覽器點，手機掃了打不開。
  • 員工 App 只在模擬器上測過：模擬器和 Mac 共用網路，App 裡的 localhost 就是這台 Mac。裝到實體手機要把 App 的後端位址換成 Mac 的區網 IP，這條沒有實測過。

遇到問題怎麼辦？

重點

先跑 bash scripts/manual-env/status.sh，大部分問題它那幾行就看得出來。後端與網頁的 log 在 ~/.tms-manual-env/backend.log 與 ~/.tms-manual-env/web.log。

下面每一條都是實際走流程時碰過、或腳本裡已經處理過的情況。點開看原因與解法。

員工 App 帳號密碼都對，卻登不進去

App 連哪個後端是編譯時決定的（編譯參數 --dart-define=API_BASE_URL），不是登入時。沒指定時預設連 8080。跑過員工 App 的驗收測試（app/bdd）後，模擬器上的 App 會被換成連 8080 或 8081 的版本，它問的是驗收測試的後端，當然找不到手動環境的帳號。

跑 status.sh 看「員工 App」那行；說不是連 8083，就跑 bash scripts/manual-env/app.sh 重新編譯並重裝。

模擬器開機了，卻看不到視窗

有些 Xcode 版本沒有獨立的 Simulator.app，open -a Simulator 會失敗。這時從 Xcode 選單 Open Developer Tool → Simulator 打開視窗。xcrun simctl list devices available 可以看有哪些機型。

flutter run 不知道要填哪個裝置

改用 bash scripts/manual-env/app.sh --run。它會挑好模擬器，並帶上連 8083 的參數。

住客頁顯示「請洽櫃檯」

最常見的原因是重灌過資料：每次 seed.sh（或不加 --keep-data 的 up.sh）都會換掉所有房間的 QR 代碼，舊網址與印出來的總表全部失效，重跑 qr.sh 拿新的。另一個原因是那間房現在沒有在住的訂單，status.sh 會列出目前的在住房。

手機掃了 QR 卻打不開

先跑 status.sh，網頁那行要聽 *:5300；不是的話跑 bash scripts/manual-env/up.sh --keep-data --phone。再確認 macOS 有允許 node 的連入連線，以及手機與 Mac 在同一個 Wi-Fi；Wi-Fi 擋裝置互連時改用手機熱點。

按了「開始」卻被擋下來

一個人同時只能有一件進行中的工作。hk1、mt1、mg1 在示範資料裡已經各有一件，做房務與工務請換 hk2、mt2。

後端起不來，或打包失敗

看 ~/.tms-manual-env/backend.log 的最後幾十行。打包要 JDK 25，up.sh --build 用 /usr/libexec/java_home -v 25 找。8083 被別的程式佔用時 start.sh 會停下來，不會去殺它。網頁的問題看 ~/.tms-manual-env/web.log。
