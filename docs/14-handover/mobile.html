員工 App 是怎麼組起來的

一套程式碼、三種殼（房務／工務／主管）。狀態管理、路由、網路都沒有用第三方套件，全部是 Flutter 內建元件自己組的。程式在 app/mobile/，以下路徑都相對它。

約 8 分鐘

程式碼是怎麼分層的？

重點

lib/ 底下只有三樣：main.dart、core/（跨功能基礎）、features/（各畫面）。登入後依角色選殼；資料模型全部擠在 core/api_client.dart。

main.dart（54 行）依序：初始化 → SemanticsBinding.ensureSemantics()（強制建立無障礙樹，Appium 才看得到元素，main.dart:15）→ TestBackdoor.maybeStart() → 安裝推播權杖服務 → runApp。

外層是 CupertinoApp，首頁 LoginScreen；全域的 rootNavigatorKey（main.dart:11）讓推播能從任何地方導頁。

登入後由 core/landing.dart:6-15 的 landingShellFor 決定殼：主管 → ManagerShell，部門是工務 → EngineeringShell，其他 → HousekeepingShell。主管再細分房務主管（可查房、可驗收）與工務主管（只能驗收），見 core/landing.dart:17-37 的 ManagerKind。

狀態管理與路由為什麼都是自刻的？代價是什麼？

重點

全部用 Flutter 內建元件：ValueNotifier 單例管狀態、Navigator 直接 push。好處是相依極少；代價是沒有路由表、「誰改了這個狀態」只能靠搜尋。當初為什麼這樣選，repo 裡沒有寫。

  • 狀態：StatefulWidget＋ValueNotifier／ChangeNotifier 單例＋InheritedWidget（Flutter 內建、把資料往下傳給子元件的機制）。
  • 路由：沒有命名路由表，Navigator＋CupertinoPageRoute 直接 push；登入後用 core/navigation.dart 的 replaceAllRoutes 換掉整個堆疊。底部分頁列是自刻的 tms_tab_bar.dart。
  • 依賴注入：靜態單例，ApiClient.instance（api_client.dart:14，測試可替換）、PushGateway.instance、ConnectionStatus.instance、OfflineQueue.instance 等；推播層另有抽象介面（push_token_service.dart:7-27）方便測試換假實作。

代價：推播深連結的導頁全部靠 PushGateway 手寫判斷；資料模型與請求擠在同一個 1795 行的檔案，features/task/task_screen.dart 也有 1835 行。要拆時再拆，不需要一開始就重構。

三個狀態的實例 — 今日資料、切分頁並高亮、主管佇列計數
  • features/today/my_today_scope.dart 的 MyTodayScope 抓 GET /me/today 往下提供。
  • features/shell/main_shell.dart:15-31 的 MainShellTabRequest 是靜態 ValueNotifier，推播要「切到待認領並高亮某張卡」時用它。
  • features/manager/manager_queues_store.dart 存主管佇列計數。

App 怎麼跟後端說話、怎麼收推播？

重點

連哪個後端是編譯期決定的，換環境要重新編譯。token 只放記憶體，沒有逾時、重試或統一的 401 處理。推播點開後由 core/push_gateway.dart 決定開哪一頁。

  • 連哪個後端：--dart-define=API_BASE_URL=...，預設 http://localhost:8080/api/v1（core/api_client.dart:9-12）。沒有環境檔、沒有執行期切換畫面；simulator 的 localhost 就是 Mac 本身。
  • 登入：POST /staff-accounts/login，body 只有 {loginId, password}（api_client.dart:35-39）。App 登入畫面沒有飯店代碼欄位，後端怎麼決定飯店見 Java 後端。mustChangePassword 為真時導到強制改密碼頁；429 加 remainingMinutes 表示帳號被鎖。
  • token 只放記憶體（api_client.dart:22），重開 App 要重新登入；每個請求帶 Authorization: Bearer。
  • 傳輸：每個請求新開一個 HttpClient、用完關掉（api_client.dart:439-476）。沒有逾時、自動重試、攔截器、統一 401 處理。
  • 冪等：寫入請求帶 idempotent: true 就自動加 Idempotency-Key（UUID v4，api_client.dart:478-487）——同一操作重送時後端回放上次結果，不會做兩次。
  • 錯誤：非 2xx 丟 ApiException，從 JSON {code, message, context} 解析錯誤碼（api_client.dart:490-530）。
  • 離線：沒有 SSE 或 WebSocket。OfflineQueue（core/connection_status.dart:45-120）離線時暫存寫入、恢復後依序重送（最多 5 次、間隔 300ms）；連線不穩時每 5 秒輪詢今日資料。但這兩個旗標只有測試後門會設定，正式環境沒有偵測網路的程式。

推播收到後，App 怎麼決定打開哪一頁？

登入成功後 PushTokenService 啟動：初始化 Firebase → 要通知權限 → 取 FCM 權杖 → PUT /me/push-token {deviceFingerprint, pushToken, platform}；登出時 DELETE /me/push-token。裝置指紋是存在 SharedPreferences 的 UUID。

點通知有三個來源：FCM 的「App 在背景時點開」、冷啟動時的初始訊息、iOS 原生的 MethodChannel com.athena.tms/push（ios/Runner/AppDelegate.swift）。同一個訊息 5 秒內只處理一次。

payload 有 target 時解析成 {kind: task | ticket | pool | home, taskId, dept, highlightTaskId}（core/push_target.dart）：task 先打 GET /tasks/{id} 查房號再導頁；pool 切到待認領分頁並高亮；ticket 開工務單頁；home 重建殼。

firebase_messaging 17 把取權杖的舊方法標成過時，但新方法回的是另一種 id、不是後端要的 FCM 註冊權杖，所以程式刻意用 // ignore: deprecated_member_use 繼續用舊方法（檔頭註解有寫原因）。

App 和自動測試之間有什麼約定？

重點

App 驗收找元素只靠 Semantics identifier，改名等於改 API；新畫面或按鈕一定要加。測試版 App 另外內建一個 9099 埠的測試後門，正式版不存在。

  • 一律用 core/tms_semantics.dart 的 TmsSemantics(id: ...) 包裝，它設了 container: true。
  • 可停用的元件要明確傳 enabled：CupertinoButton(onPressed: null) 不會把停用狀態寫進無障礙樹，測試會判斷錯。
  • 命名是 畫面.元素 的點分隔小寫，例如 home.screen、engPool.screen、me.logout-button、home.task.<房號>.card、ticket.stepper.<n>--current、system.offline-bar。全專案兩百多處；主管相關的集中在 features/manager/manager_ids.dart。

測試後門只有以 --dart-define=TEST_BACKDOOR=true 編譯的 App 才會開（core/test_backdoor.dart），在 127.0.0.1:9099 提供撥時鐘、讀狀態、模擬斷線等能力，也會寫一份 log 到系統暫存目錄的 tms_backdoor_log.txt。

本機怎麼跑、怎麼打包？

重點

本機開發一律帶 API_BASE_URL 指到手動環境 8083，否則會連到被測試清空的 8080。正式打包、簽章、上架在 repo 裡沒有腳本也沒有文件。

cd app/mobile
flutter pub get
flutter test                                  # 約 60 個 widget／單元測試檔；沒有 integration_test/
flutter run -d <simulator> --dart-define=API_BASE_URL=http://localhost:8083/api/v1
App 驗收用的建置指令 — run-*.sh 會自動執行，通常不用手打 
flutter build ios --simulator --debug \
  --dart-define=TEST_BACKDOOR=true --dart-define=API_BASE_URL=http://127.0.0.1:8080/api/v1

test/support/test_environment.dart 把 widget 測試的視窗設成 402×874 並關掉動畫，避免 pumpAndSettle 逾時。

正式打包的標準指令是 flutter build ios 或 flutter build apk|appbundle 加上 --dart-define=API_BASE_URL=<正式網址>。ios/Runner/Info.plist 沒有 App Transport Security 例外設定，實機連 http 明碼網址會被 iOS 擋下，正式環境必須用 https。

Firebase 設定檔不進版控：iOS 放 ios/Runner/GoogleService-Info.plist，Android 放 android/app/google-services.json（同目錄有 README-firebase.md 與 .example 範本）。目前兩個真檔都沒有，App 照樣能跑，只是推播停用、初始化失敗印一行 log。Android 只有 json 存在時才套用 google-services 外掛（android/app/build.gradle.kts:7-9）。

Android 上線前還有幾個洞，見坑與待查。

介面語言、主題與稱謂是怎麼處理的？

重點

沒有多語系框架，文案是中文硬寫在程式裡；唯一的語言切換只影響登入頁。對使用者一律稱「您」。

主題在 core/theme.dart（TmsColors、TmsText、TmsSpacing、TmsRadius、TmsSize），品牌主色 #0C7680；以 Cupertino 為主、Material 只用於 Theme。

登入頁的 LoginLanguage 有 zh-Hant、zh-Hans、en、ja、vi 五種（login_language.dart:8-14），只影響登入頁本身。
