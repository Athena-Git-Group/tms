三層之間

這個市場分成三層：住客層、營運任務層、PMS 層。 Flexkeeping、Optii、Quore、Sweeply、HotSOS 全在中間那層，而中間那層沒有資料主權—— 這就是 Mews 能把 Flexkeeping 買走的原因。你們的差異化不在功能，在你們同時站在三層上。

00 — 更正

「預估 vs 實際工時」不是護城河

先前的判斷錯了

我之前說「Flexkeeping 只有預估工時、沒有量測實際起訖，所以預估與實際的落差是你的差異化」——這個結論在整個類別的層次上是錯的。

Optii 已經做得更深：用機器學習依房客類型、住宿長度、房型與歷史資料預測每間房的清潔時間，再據此最佳化房務人員的走動路線。官方宣稱房務人員產能提升最多 20%、主管 40%、人力成本降最多 15%；一份 2026 年的第三方實測確認「AI 確實有效、人力節省是真的，只是沒有宣稱的 18% 那麼高」。

Quore 也有依入住預測動態調整人力配置的功能。工時量測與派工最佳化在這個類別已經是標配，不是賣點。

這個更正很重要，因為它把你的差異化敘事從「我們能算出工時」逼回到真正站得住腳的地方。往下看第 03 節。

這裡要更正我自己前一版的說法

我前一版寫「台灣本地 PMS 不在整合清單上，整合不了產品就進不來」。查完 Sweeply 之後，這個說法太強了。

兩個反證：一、Sweeply 可以完全不接 PMS 獨立運作；二、要新做一個 PMS 整合，客戶確定買之後只要 2–3 週。所以整合不是牆，是摩擦。

剩下的真實障礙比較小但仍然存在：2–3 週是「客戶先承諾之後」才開始算，所以需要有台灣客戶先想要他們想要到願意簽——這是雞生蛋問題。而獨立運作模式會失去自動化價值（房況要手動維護），那正是我們第一天討論時否定掉的路線 C。

台灣市場：查無公開資料，不要當成護城河

這五家在台灣的在地化、繁中介面、本地經銷，我查不到任何公開資訊。這是「查無資料」，不是「確定沒有」。

可以合理推論的是：沒有任何一家的整合清單出現台灣或華語 PMS，亞太客戶數也極少（Sweeply 亞太 1 家）。所以「他們現在不在這裡」大致成立，但「他們進不來」不成立。進入台灣對他們是投報率問題，不是能力問題。

03 — PMS 那一層

他們的房務模組有多深

Cloudbeds / Mews / Little Hotelier / RoomRaccoon 四家都有房務功能，但深度差很多——而且這一層你們是既有玩家，不是挑戰者。

PMS房務模組現況對你的意義
Mews整合房務、即時房況。但房務行動版屬於加購訂閱，不含在基本方案買了 Flexkeeping 之後這塊會補強。最該盯的一家
Cloudbeds有房務模組，但比較評測指出僅有基本房況、沒有專屬房務 App深度不足 → 這正是 Flexkeeping 這類產品存在的空間
RoomRaccoon房務行事曆與通知中小型全包型，深度有限
Little Hotelier小型旅館用的基本房況與清潔提醒最淺。這一層確認了中小型市場的房務工具是空的

這張表的重點不是誰強誰弱，是一個模式：PMS 廠商的房務模組普遍停在「房況顯示」，沒有走到派工最佳化與工時量測，而且行動端常常要加購。這是整個營運任務層存在的理由。

但 Mews 買下 Flexkeeping 代表這個空間正在被收斂。三年內，「PMS 自帶像樣的房務模組」大概會變成標配——你們如果要做，時間窗不是無限的。

04 — 差異化

你真正不一樣的地方，按強度排序

01你們同時擁有 PMS 與任務層結構性 · 最強

上面那五家每一家都是一個必須整合的夾層。他們要談合作、要看別人的 API 臉色、要承擔整合壞掉的風險、而且永遠拿不到訂單與帳務資料。Flexkeeping 被 Mews 買走就是這個結構的必然結果。

你們從他們的終點出發：零整合成本、單一供應商責任、可以直接雙向寫房況與 minibar 計費而不需要任何合作協議、bundle 定價可以低到他們追不上。

風險：這條優勢百分之百建立在「客戶已經在用你們的 PMS」。離開這個前提，你就只是一個沒人聽過的台灣 task 工具在跟 Optii 比功能表。

02員工端在 LINE 上，不是 App在地 · 難複製

這不是「翻譯成中文」，是通道不同。歐美產品的員工端預設是自家 App 或 WhatsApp／Slack；台灣、日本、泰國的旅宿員工整天都在 LINE 上。

要 Optii 或 Quore 為台灣市場重做一個 LINE LIFF 員工端，投資報酬率對他們不成立——市場太小。這是典型的在地護城河：不是技術難，是對方不值得做。

風險：LINE 推播有訊息量費用，且員工要加官方帳號為好友。成本模型與 web 備援要先算清楚（已列在待決事項）。

03業務履約報告真實但未驗證

公司戶合約承諾 → 入住前自動展開跨部門任務 → 退房後產出履約報告。這需要同時握有任務軌跡（營運層）與合約／corporate account（PMS 層）。

Flexkeeping、HotSOS 有任務軌跡但沒有合約資料；PMS 有合約但沒有任務軌跡。只有跨兩層的人做得出來。這條在我更正掉工時那條之後，變成你功能面最站得住的差異化。

風險：完全沒有客戶驗證過。四五星業務是否真的會用這份報告去談續約，是假設不是事實。

04定價帶與導入成本可被跟進

HotSOS $20–45／使用者／月，300 房配 100 位使用者就是每月 $2,000–4,500。Optii per-room 且價格保密。台灣四五星付這個價會很痛，而你可以用 PMS 客戶的 bundle 價進場。

但 Sweeply 的模式要小心：依可售房計費、使用者不限、後場與走道不計費。對 300 房配 100 員工的飯店，這比 per-user 便宜一個量級，而且可預測。你的定價設計應該對標 Sweeply 的模式，不是對標 HotSOS 的。

風險：價格優勢是最容易被跟進的，而且已經有人（Sweeply）用更友善的模式在做。競品降價或推 lite 版就沒了。絕對不要把它當成核心敘事。

以下這些不要當成賣點

拿去跟客戶講，對方只要有做過功課就會反問「Optii 也有啊」。

功能比較表你一定會輸

Optii 做這件事超過十年，Flexkeeping 從 2012 年開始，HotSOS 更久。你是 v0。任何逐項打勾的功能比較表，你都會被比下去。

所以銷售敘事不能建立在功能上，要建立在「我們是同一家公司、你已經在用我們、零整合、繁中與 LINE、在地支援」——這些是他們無法在比較表上反駁的。

05 — 結論

這份分析回答了那個未決問題

第一市場不是偏好問題，是唯一可行的問題

你昨天留著沒決定的是：先打現有四五星 PMS 客戶，還是先打中小型旅宿。

競品地圖給出的答案很清楚：你唯一的結構性優勢（差異化 01）只在客戶已經使用你們 PMS 時存在。離開這個前提，你在跟 Optii、Flexkeeping、HotSOS 比功能，而你是 v0。

所以第一市場必須是現有四五星 PMS 客戶。這不是因為它比較好賣，是因為另一條路上你沒有任何結構性優勢。

那中小型旅宿呢

那個市場確實是空的——Flexkeeping 進不來（沒有可整合的 PMS）、HotSOS 太貴、Optii 定位太高端，只有 Sweeply 瞄準小型旅館。

但你在那裡同樣沒有 PMS 優勢（那些客戶不用你們的 PMS），而且要自帶輕量 PMS 才能拿到房況。所以它是第二市場，而且進入條件是「先在四五星把產品做熟，再往下做一個簡化版」——不是反過來。

時間壓力：Mews 買下 Flexkeeping 代表 PMS 自帶像樣房務模組正在變成標配。你們作為 PMS 廠商做這件事是順勢而為，但窗口不是無限的。
